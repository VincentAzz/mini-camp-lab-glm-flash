## 2. 车型模块公共技术约定（五车共享，写一次、五处引用）

### 2.1 世界尺度与落位基准（【3·总则-2】【3·总则-6】）

- 坐标约定：每车局部坐标系 **+X = 车头方向、+Y = 上、+Z = 左侧**；模块只在自己的 `ctx.root` 下建模，对位（位置/朝向/接地）由 Director 按场景 `campAnchor` 完成，车辆自身不读场景。
- 尺度：以「1 单位 ≈ 0.9 m 观感」设计，五车尺寸（长×宽×高，高为展开态总高）：

| 车型 | 长×宽×高 | 定位 |
|---|---|---|
| C 型 | 6.4 × 2.3 × 3.0 | 紧凑双层，升顶+滑出 |
| A 型 | 9.0 × 2.5 × 3.3 | 大巴长轴，单层大厅 |
| 皮卡+拖挂 | 组合 9.8 × 2.3 × 2.6（拖挂） | 双体纵列 |
| B 型 | 4.7 × 2.0 × 2.9（升顶态） | 最小单体 |
| 越野皮卡 | 5.2 × 2.1 × 3.4（含车顶帐篷展开外伸） | 高底盘 |

- 接地适配（用 `ctx.camp` 快照，字段名与 10-架构 §3.3 一致）：`root.y = camp.groundY`（车轮触地由车辆内部保证：轮胎外缘最低点 = 局部 y=0）；朝向直接用 `camp.headingRad`，仅拖挂组合额外 +0.06 rad 微调使车头略偏（「轻微适配」示例）；**越界告警**：若 `footprint` 外接圆半径 > `camp.radius`，`console.warn('[vehicle] footprint exceeds camp radius')`，不阻断装配。
- 营位半径契约：本章按「`camp.radius ≥ 5.5`」设计（拖挂组合 9.8 长的外接半径 ≈ 5.1）。若场景章定出的半径更小，属场景章契约冲突，回写两章协商——列入 §11 遗留。

### 2.2 程序化建模四大手法（geom/ 层，全部代码生成，八.2 L121）

1. **圆角盒 `roundedBox(w, h, d, r, seg=2)`**：2D 圆角矩形 `Shape` → `ExtrudeGeometry`（depth=d，bevel 0.03）。用于柜体、沙发、床垫、设备箱等一切「带厚度的方物」，杜绝生硬直角。
2. **侧影挤出 `profileExtrude(points2D, width, bevel)`**：以**车身侧影轮廓点列**建 `Shape`，沿 Z 挤出整个车宽；**开窗即开洞**——侧窗/贯通侧窗/双排窗做成 `Shape.holes`（圆角矩形洞），洞沿 Z 贯通，内饰置于洞腔内，两侧各贴一片玻璃即成「真开洞」透视。用于 C 型主厢、A 型车身、皮卡车身、B 型一厢体、拖挂厢体。这是本章最关键的手法：**内饰可见性不靠假贴图，靠真开洞 + 独立内饰组**。
3. **分面拼装**：凡前挡需要弧面/斜面的车，前墙独立成一块「正影挤出面板」（0.06~0.08 厚，`Shape.holes` 挖前挡洞），弧面玻璃用 `CylinderGeometry` 开口弧段（`openEnded=true, thetaLength≈0.6rad`）贴装在洞外侧。用于 C 型凸头、A 型大巴前脸、B 型短头。
4. **Lathe/参数曲面**：卫星锅（Lathe 抛物面母线）、洗手盆（Lathe 回转体）、手冲壶（Lathe）、拖挂前鼻（圆柱+球冠缩放）。

**内饰可见性结构三件套（每车相同，解决「透过近窗看到远处穿帮」）**：
- `innerShell`：车身内衬壳 = 车身体缩放 0.94 的圆角盒，材质 `side: BackSide`、暖色系（各车不同，见 §8.1 色板）、`noOutline`、`castShadow=false` ——保证透过玻璃看到的是**暖色内壁**而不是天空；
- 玻璃：`depthWrite=false`、`renderOrder=20`、`side=DoubleSide`、`transparent`；内饰组 `renderOrder=0`；
- 内饰小件一律 `noOutline`（描边只给车体外壳，§9），避免透窗时描边碎线污染剪影。

### 2.3 「透视内饰」总策略：车窗与帐帘的三档透明（【3·总则-3】；3.1-5 / 3.3-6 / 3.4-6 / 3.5-6）

**玻璃卡通材质 `glassMat`（render/toonMaterial.ts 注册一种变体）**：
- 基底 `MeshPhongMaterial{ transparent, shininess:90, specular:#9fd8ff, side:DoubleSide, depthWrite:false }`；`onBeforeCompile` 注入菲涅尔边缘增亮（rim = pow(1−|dot(n,v)|, 3) × 0.35）与上冷下暖微渐变；
- 三档不透明度常量（集中 `content/vehicles/types.ts` 导出）：
  - `clear`：opacity **0.24** —— 大面积主窗（C 侧窗、A 贯通侧窗、B 大侧窗、各皮卡双排窗）；
  - `tinted`：opacity **0.40** —— 前挡（仪表区微遮，逼视线去看侧窗与升顶）与舷窗；
  - `porthole`：opacity **0.30** —— 圆舷窗/小窗。
- 玻璃**不随时间/天气变色**：车辆不直读时间（守 D2 依赖纪律），黄昏冷蓝/夜间深邃的氛围由全局光照 rig 打在玻璃高光与环境色上自动生效。这是本章的一条明确拍板。

**帐帘/纱帘半透材质（布料透光晕）**：升顶帐帘、后尾纱帘、遮阳幕用 `MeshToonMaterial{ transparent, opacity, emissive:#ffb066, emissiveIntensity:0 }`；`applyInteriorLight` 把 `emissiveIntensity = 0.55 × power` 写进这些布料材质 → **黄昏/夜间车内光「透过布料」洇出来**，白天 emissive=0 布料恢复本色。这是「帐帘透视」的核心手法：帘不掀开也能读到室内温暖。

- C 型升顶帐帘：帘布本体 opacity 0.85 + 上述透光 emissive；前帘做**收拢卷**（两根小圆柱卷帘挂在楔形前角），不遮挡俯视视线。
- B 型纱帘（后掀口）：opacity 0.5 + Canvas 网格 alpha 贴图 `texGauze`（64²，2px 网格线，alphaTest 0.15），室内景物隔帘呈柔化网格感。
- 越野遮阳幕：opacity 0.6 + 编织纹 Canvas 斜纹 alpha，半透不透明各半。

**可读性规则（保证「清楚看到」，三·总则 L48）**：
- 视线通廊：每扇 clear 窗对应区域内，家具高度 ≤ 窗台线（约局部 y=1.45）以下 70% 视域，高柜一律贴远墙布置，不得堵窗；
- 内饰自身带 0.12×power 的暖色 emissive 底（写在 innerShell 与主要家具材质上），暗环境（夜间）下内饰自发光可读，不依赖外部灯照进窗；
- 内饰 toon ramp 用 2 段软色阶（比车体 3 段更柔），透窗观感「暖而平」，符合微缩陈列盒的内舱观感。

### 2.4 内饰灯光钩子总约定（【3.6-2④】；决策 D2；Q6 拍板落点）

每车 `InteriorLightHooks` 的统一实现模板（唯一驱动链：`TimePreset.channels.interiorPower / interiorEmphasis` → `applyInteriorLight(power, emphasis, blend)`，车辆不自行读时间）：

```ts
// content/vehicles/<id>.ts 内（示意，各车实例不同）
const fillLight = new THREE.PointLight(0xffb066, 0, 6.0, 1.8); // 全局≤2点光预算中的「车内暖光」位
function applyInteriorLight(power: number, emphasis: number, blend: number) {
  fillLight.intensity = THREE.MathUtils.lerp(fillLight.intensity, 1.15 * power * emphasis, blend);
  for (const g of glowTags)      g.mat.emissiveIntensity = g.factor * (0.12 + 0.88 * power); // 家具/帘布透光
  for (const s of screens)       s.material.color.setScalar(0.30 + 0.70 * power);            // 屏幕类自发光
  for (const l of lamps)         l.target = l.gain * power;   // LightBreathSystem 每帧读取并叠加呼吸/闪烁
}
```

- `lamps`（LampHandle[]）交 Director 注册进 LightBreathSystem；`mode` 四选一（steady/breath/blink/rotate），呼吸与闪烁的周期、相位全部取自 RhythmClock 分频（七.5 L116「统一节奏」）。
- 每灯带 `gain`（功率增益），区分主灯与装饰灯。
- **五车灯形态拍板**（回应 Q6 / 02-存疑 3；逐车详见 x.4）：C=小夜灯(呼吸)+顶灯(恒亮)；A=通顶暖色灯带(恒亮)+床头阅读灯(呼吸)+卫浴冷光小灯(恒亮低)；拖挂=车厢顶灯(恒亮)+皮卡仪表微光(屏幕自发光)；B=车内串灯(轻快闪烁/错相)；越野=帐篷 LED 灯串(闪烁)+驾驶舱屏幕微光+车内小顶灯(恒亮低)。
- 屏幕类（大屏/仪表/中控）统一 `MeshBasicMaterial + CanvasTexture`（不受光照、天然「亮着」），钩子只调制 `material.color` 标量；黄昏档 interiorPower≈0.9（数值以时间章预设数据为准）时屏幕接近全亮，与 3.1-13「冷暖对比」互为支撑。

### 2.5 车辆布料与天气挂点总约定（决策 D3；五.3 L95 / 七.5 L116）

- **车辆全部布料件**（C 升顶帐帘带、A/拖挂/B 遮阳棚布、B 纱帘、越野遮阳幕与帐篷侧布）一律建为 `ClothHandle{ mesh, swayAxes, stiffness }` 交 WindSystem 统一驱动——车辆不写任何风力代码。参数思路：`stiffness` 帐帘/棚布 0.5~0.9（张紧、小幅摆）、纱帘/遮阳幕 0.3~0.4（柔软）；摆幅 = 阵风噪声 × (1−stiffness)。
- **积水下凹**（五.3 L95）：遮阳棚布与帐篷顶布同时注册 `WeatherSurface{ material, kind:'clothTop' }`，WeatherMaterialSystem 把 `clothSag` 写入布料 shader 的 `uSag`（中部下垂曲线 sin(πx)×uSag，雨天 0.06 单位）；**车顶积雪**（五.5 L97）：车顶面板、升顶楔顶、行李架板注册 `kind:'roofTop'`。
- 生成方式：棚布 = 预倾斜 12° 的 `PlaneGeometry(w, d, 12, 4)`，顶点位移全部在 WindSystem/WeatherMaterial 的共享 shader uniform 完成（CPU 零逐顶点，§9）。

### 8.2 细节量量化核对（【3·总则-5】，回应 02-存疑 4 的口径拍板）

口径 = **双指标**：① `VehicleInterior.named` 组数（内部清单逐项落点的直接度量）；② 外部要素行数（x.1 表行数，勾验时逐行核对）。基准 C 型 = 16 / 22：

| 车型 | named 组数 | ≥C(16)？ | 外部要素行数 | ≥C(22)？ | DeploymentPart | lamps | cloths | weatherSurfaces |
|---|---|---|---|---|---|---|---|---|
| C 型（基准） | 16 | = | 22 | = | 2 | 2 | 1 | 3 |
| A 型 | 17 | ✓ | 24 | ✓ | 2 | 3 | 1 | 4 |
| 皮卡+拖挂 | 16（10+6） | ✓ | 25 | ✓ | 4（jackLeg×2 合 1 组声明 2 件+awning+other 桌板） | 1 | 1 | 3 |
| B 型 | 16 | ✓ | 23 | ✓ | 3 | 2 | 3 | 3 |
| 越野皮卡 | 16 | ✓ | 24 | ✓ | 3 | 3 | 2 | 4 |

> 口径说明：named 组数按「原文清单逐项 + 少量支撑细节（地板/前排座等）」构成，支撑细节只增不减；任何一车若实现时跌破 16/22 即视为【3·总则-5】不达标，进 TASKS.md 阻断项。字数级「密度感」另由 §2.3 可读性规则（通廊不堵窗 + 暖色内衬）保证观感不空洞。

## 9. 性能预算与描边策略（八.3 L122；10-架构 §7 落点）

- **单车型装配**：同屏永远只有一辆车（Director 切换时旧车反注册并 dispose），内饰「常驻可见」不产生多车叠加成本。
- 每车 draw call 预算（含 OutlineSystem 反壳与布料，目标 ≤40，全组合 ≤200 的车辆侧份额）：

| 车型 | 估算 DC（本体+内饰+粒子无关件） | 其中描边壳 |
|---|---|---|
| C 型 | ~32 | 4（厢体/舱段/凸头/升顶楔） |
| A 型 | ~36 | 3 |
| 皮卡+拖挂 | ~38 | 5 |
| B 型 | ~28 | 3 |
| 越野皮卡 | ~34 | 4 |

- 实例化落点：轮毂凸块/书册/柴火/灯串灯泡/格栅条/织带全部 InstancedMesh；同 id geometry（wheel、ladder、jerryCan、toolbox）经 SharedAssets 跨车复用。
- 阴影：车体壳 castShadow=true；玻璃/内饰/布料 castShadow=false（布料影由棚布倾斜投影近似）；车顶帐篷在地面投下展开影（走主方向光 shadow map）。
- 动效全 shader 化：布料摆动与积水下凹 = WindSystem/WeatherMaterial 共享 uniform（uWind/uSag），灯效 = LightBreathSystem emissive 调制，CPU 每帧零逐顶点。
- 估算值为设计预算，待 Engine dev 计数器（10-架构 §7-8）实测后回填本表——列入 §11 遗留。

## 10. 注册表接线与扩展验证（【3.6-1…4】）

### 10.1 接口照用声明（3.6-2：四项逐字段对应 10-架构 §3.3，零增删）

每个车型文件实现且仅实现 `VehicleModule` 四项：`buildExterior`（=外部模型，含 footprint/paint/windows/cloths）、`buildDeployment`（=展开机构，DeploymentPart 枚举 kind+deployAmount=1）、`buildInterior`（=透视内饰，named 键表）、`interiorLightHooks`（=内饰灯光钩子，lamps+applyInteriorLight）。本章未对 `core/`、`render/`、`systems/`、`ui/` 提出任何新接口；§2.3 的 `glassMat`、§2.6 的贴图工厂、§2.7 的 vehicleKit 分别落在 render/toonMaterial.ts 变体注册、tex/、geom/parts/vehicleKit.ts 三个既有落点上。

### 10.2 五车注册行（content/vehicles/registry.ts，与 10-架构 §3.3 末尾一致）

```ts
vehicleRegistry.register(classC);        // isDefault: true  【3.1-1 默认车型】
vehicleRegistry.register(classA);
vehicleRegistry.register(trailerRig);    // 决策 D4：单模块
vehicleRegistry.register(classB);
vehicleRegistry.register(overlandTruck);
```

### 10.3 与公共系统/场景的接线清单（每车装配时交出）

| 交付物 | 去向 | 驱动 |
|---|---|---|
| `cloths[]` | WindSystem | 阵风噪声×(1−stiffness)；雨天 clothSag 经 WeatherMaterial 写 uSag |
| `interiorLightHooks.lamps[]` | LightBreathSystem | interiorPower×gain，叠加 breath/blink（RhythmClock 节奏） |
| `weatherSurfaces[]` | WeatherMaterialSystem | snowCover（roofTop）/clothSag（clothTop） |
| `windows[]` | Director 记录 + glassMat 创建 | 静态；不做运行时开关（透明度即语义） |
| `DeploymentPart[]` | Director 记录 | 默认展开交付；数值保留给未来展开动画 |
| `footprint` / `paint` | campAnchor 对位 / 材质参数 | 越界告警；weathering 预留默认关（Q2） |

车型切换走 10-架构 §5.3 次重路径：600ms 淡出 → 反注册 cloths/lamps → dispose（SharedAssets 引用计数释放 vehicleKit geometry）→ 新车按当前 campAnchor 对位 → `applyInteriorLight(当前时间档值, blend=1)` 立即呈现 → 600ms 淡入。

### 10.4 扩展验证（3.6-3）

引 10-架构 §6.2 结论：新增车型 = 新建 `content/vehicles/<id>.ts` 实现 VehicleModule 四项 + registry 一行，`core/`、`render/`、`systems/`、`ui/`、四个场景文件全部零改动（场景只提供 campAnchor）。本章五车全部按此纪律建模，未要求任何核心改动——3.6-3 的硬性要求在本章方案内自洽成立；3.6-4（与八.4 互证）由 10-架构 §3.6 独立性核对表覆盖。
