## 1. UI 层在架构中的位置与数据流

### 1.1 承接关系

UI 是架构章 §2 分层图中的 `ui/` 层，向下只允许依赖 `core/`（state/events/registry）与自身文件；**严禁 import `content/`**（架构章 §1 依赖纪律 1）。UI 渲染所需的一切内容信息（有哪些场景/车型/时间/天气、显示名）只经两条通路获得：

1. **枚举通路**：`sceneRegistry.list()` / `vehicleRegistry.list()` / `timeRegistry.list()` / `weatherRegistry.list()`（架构章 §3.1 `Registry.list()`，保持注册顺序）→ 分段按钮按注册顺序渲染。**注册表新增一行，按钮自动出现**——落实 2.5 L44 / 3.6 L77"登记即可被 UI 与切换逻辑识别"（架构章 §1 纪律 4、§6 扩展示例第 4 行）。
2. **状态通路**：`core/state.ts` 的 `AppState`（架构章 §2："scene/vehicle/time/weather 四维当前值 + 变更事件"）+ `core/events.ts` 事件总线 → 选中态、标题条、过渡触发。

### 1.2 完整数据流（点击一次"小雨"按钮）

```
用户点击[小雨]（ControlPanel，DOM）
  → AppState.set('weather','rain')        // core/state.ts：registry.get('rain') 校验；同值 no-op
  → EventBus 'state:change' {dim:'weather', id:'rain', entry:WeatherPreset}
      ├─ ControlPanel                      // 更新选中态 aria-pressed + 标题条文字（§3）
      └─ TransitionController              // core/transition.ts（架构章 §5.3 路由）
            → 粒子交叉淡入淡出（ParticleSystem，1500ms，§6.4）
            → WeatherMaterialSystem 共享 uniform 插值（wetness…，1500ms）
            → WindSystem.setWind(windMul×基准)（指数趋近，§6.4）
            → lightMod 乘入全局光照（夜间浓雾=更暗+更强光晕，五-6 L98）
            → scene.lightHooks / vehicle.interiorLightHooks 按插值后状态每帧下发
```

### 1.3 HUD 纪律（一.4 L10、一.3 L9）

整个页面 DOM 只有四个固定件：**标题条（左上）+ 控制面板（底部居中）+ 隐藏钮（右上）+ 隐藏态幽灵把手（右上）**。画面本身（WebGL 画布）不渲染任何文字/徽标/水印；架构章 §7#8 的 draw-call 计数器等 dev HUD 仅在 `import.meta.env.DEV` 下由 ControlPanel 渲染，产物构建中不存在。favicon 用内联 SVG data URI（架构章 §2 index.html 注），零网络请求。

### 1.4 指针事件分层

`#ui-root { position: fixed; inset: 0; pointer-events: none; }`，所有可交互子元素单独恢复 `pointer-events: auto`。**画布在 UI 元素之外的任何位置都可以直接拖拽旋转**，UI 不会"挡住"一块不可交互的死区。

## 2. 六.1 分组切换控件

### 2.1 形态选型：分段按钮（六.1"分段按钮**或**卡片列表"二选一）

**选分段按钮**，理由：①四组按钮常驻可见，400 组合巡游（十一.2 L151）是本玩具的核心玩法，卡片列表展开/收起会给每次切换多加一步；②分段按钮天然呈现"当前档在序列中的位置"（如 夜间 是时间四档的第 4 档），选中态比卡片更清晰；③高度可控，满足"小巧克制、不遮挡模型主体"（六.3 L104）。

渲染代码只信注册表，**按钮顺序 = 注册顺序、文案 = `RegistryEntry.label`、选中态 = `AppState` 对账**：

```ts
// ui/ControlPanel.ts（消费架构章 §3.1 Registry / §2 state.ts）
const DIMS = [
  ['scene',   sceneRegistry,   '场景'],
  ['vehicle', vehicleRegistry, '车型'],
  ['time',    timeRegistry,    '时间'],
  ['weather', weatherRegistry, '天气'],
] as const;

for (const [dim, registry, label] of DIMS) {
  for (const entry of registry.list()) {            // 注册顺序即按钮顺序（架构章 §1 纪律 4）
    const btn = makeSegButton(dim, entry);          // entry.id 驱动图标选择（§2.4），entry.label 即文字
    btn.addEventListener('click', () => state.set(dim, entry.id));  // 非法 id 由 registry.get 抛错
    segments[dim].append(btn);
  }
}
stateBus.on('state:change', ({ dim, id }) => syncPressedState(dim, id));  // 程序化 set（如后续加 URL 参数）也走同一入口
```

### 2.4 图标：`ui/icons.ts` 内联 SVG 程序化生成（六.1"图标+文字"，承接 D7）

统一规范：`viewBox="0 0 24 24"`、`fill="none"`、`stroke="currentColor"`、`stroke-width="1.6"`、`stroke-linecap/linejoin="round"`、`aria-hidden="true"`。旋转对称图形**用循环生成**而非手抄路径，坐实"程序化"（八.2 L121）：

```ts
// ui/icons.ts —— 零图标包、零字体、零图片资产（D7 / 八.1 L120 / 八.2 L121）
const S = (body: string) =>
  `<svg viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.6"
        stroke-linecap="round" stroke-linejoin="round" aria-hidden="true">${body}</svg>`;

const line = (x1:number,y1:number,x2:number,y2:number) =>
  `<line x1="${x1.toFixed(2)}" y1="${y1.toFixed(2)}" x2="${x2.toFixed(2)}" y2="${y2.toFixed(2)}"/>`;

/** 太阳：8 道光芒循环旋转生成（time:day 与 weather:clear 复用，r 可区分大小） */
export function iconSun(r = 4.2, rays = 8): string {
  let arms = '';
  for (let i = 0; i < rays; i++) {
    const a = (i / rays) * Math.PI * 2;
    arms += line(12 + Math.cos(a)*(r+1.6), 12 + Math.sin(a)*(r+1.6),
                 12 + Math.cos(a)*(r+4.0), 12 + Math.sin(a)*(r+4.0));
  }
  return S(arms + `<circle cx="12" cy="12" r="${r}"/>`);
}

/** 雪花：6 臂 + 每臂两根 45° 分叉，循环生成（weather:snow） */
export function iconSnowflake(arms = 6): string {
  let d = '';
  for (let i = 0; i < arms; i++) {
    const a  = (i / arms) * Math.PI * 2;
    const dx = Math.cos(a), dy = Math.sin(a);
    d += line(12, 12, 12 + dx*8.5, 12 + dy*8.5);
    for (const t of [5.2, 7.6]) {
      d += line(12 + dx*t, 12 + dy*t,
                12 + dx*t + Math.cos(a+0.79)*2.2, 12 + dy*t + Math.sin(a+0.79)*2.2);
      d += line(12 + dx*t, 12 + dy*t,
                12 + dx*t + Math.cos(a-0.79)*2.2, 12 + dy*t + Math.sin(a-0.79)*2.2);
    }
  }
  return S(d);
}
```

### 2.7 可达性（不新增原文要求，工程基线）

### 2.8 响应式（<720px 或面板高度 > 视口 40% 时）

面板自动切换为「页签条 + 单组展开」：底部一条 56px 高玻璃条，横向排 4 个维度页签（图标+字）；点页签在该条上方弹出对应组的分段按钮行（超宽横向滚动，滚动容器 `scrollbar-width:none`）；再点其他页签切换组。切换由 CSS class 驱动（`.panel.compact`），JS 只按 `(max-width: 719px)` 媒体查询 + `matchMedia().addEventListener('change')` 加减 class，不做 JS 布局计算。

- **格式**：`[scene.label, vehicle.label, time.label, weather.label].join(' · ')`，如「山间松林 · 拖挂房车 · 夜间 · 小雨」。分隔点 `·` 用 `var(--accent)` 着色，四个词用正文色——一眼可分四个维度。
- **更新动画**：内容变化时旧文本 `translateY(-8px)+opacity→0`（140ms ease-in）、新文本自 `+8px` 淡入（180ms ease-out），总时长 300ms 内完成，不与场景切换的 600ms 淡入淡出抢戏。实现：双 span 交替（`.title-chip__a/__b`），JS 切 class。
- **省略策略**：`max-width: 46vw; overflow:hidden; text-overflow:ellipsis; white-space:nowrap;`——label 按短名约定（§2.6）正常不会溢出；若用户后续自定义超长场景名，省略号兜底。
- **数据来源**：纯 `AppState` + 四注册表 `get(dim).label`，UI 不缓存文案副本；注册表 label 改名标题自动跟随。
- **附属小圆点**：chip 左侧一枚 6px 圆点，填充 `var(--accent)`（随时间档变色，§4.3）——纯装饰，不给它加任何含义，避免变成需要解释的 HUD。

## 4. 六.3 磨砂玻璃视觉系统（uiStyle.css）

### 4.1 玻璃基线参数（半透明/圆角/细描边/柔和阴影逐项定值）

```css
/* ui/uiStyle.css —— 六.3 L104 四个关键词各落一个属性 */
.glass {
  position: fixed; z-index: 10;
  /* 半透明：深色玻璃基线（理由见 §4.2），165° 微渐变给"玻璃厚度" */
  background: linear-gradient(165deg, rgba(40,47,78,.46) 0%, rgba(21,26,48,.40) 100%);
  -webkit-backdrop-filter: blur(18px) saturate(1.45);   /* 磨砂：模糊+提饱和，透出三渲二底色 */
  backdrop-filter: blur(18px) saturate(1.45);
  border: 1px solid rgba(255,255,255,.22);              /* 细描边：1px 白 22% */
  border-radius: 18px;                                  /* 圆角：面板级 18 / 按钮级 9 / 圆钮 999px */
  box-shadow: 0 10px 32px rgba(8,12,28,.35),            /* 柔和阴影：大半径低透明度 */
              inset 0 1px 0 rgba(255,255,255,.16);      /* 顶部内高光：玻璃上缘反光 */
  color: #eef2ff;
  font: 12px/1.4 system-ui, -apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif;
}
@supports not ((backdrop-filter: blur(1px)) or (-webkit-backdrop-filter: blur(1px))) {
  .glass { background: rgba(20,25,45,.84); }            /* 降级：不透明显著提浓，保证可读性 */
}
```

三块玻璃件（chip / panel / 隐藏钮）共用 `.glass`，尺寸差异用 modifier（`.title-chip { border-radius:999px }` 等）。

### 4.2 为什么是深色玻璃基线

400 组合中夜景/黄昏/浓雾/末世夜占观感暗色的一半以上（四-4 L86"所有灯光点亮"、五-6 夜间浓雾等）；浅色玻璃在暗场景上会成为画面中最亮的块，抢走"车内暖光成为深夜温暖焦点"的主角地位（四-4 L86）。深色玻璃在亮场景（白天晴朗）上则表现为柔和的深窗感，与三渲二的干净底色兼容。文字对比度按最不利组合校验：正文 `#eef2ff` 对白天亮底透过 18px blur 后的混合底色 ≥ 4.5:1（WCAG AA）。

### 4.3 强调色随时间档联动（UI 与三渲二美术统一的锚点）

六.3 要求"UI 风格**与三渲二美术统一**"——除磨砂玻璃质感外，再取时间档的色相作 UI 强调色。ControlPanel 在 `state:change{dim:'time'}` 时写两个 CSS 变量（**JS 预计算 rgba 字符串，不用 `color-mix()`**，规避旧内核兼容问题）：

| 时间档 | --accent（hex） | --accent-dim（选中底） | --accent-line（选中描边） |
|---|---|---|---|
| dawn 清晨 | `#9fd8ff` 青金晨光 | `rgba(159,216,255,.20)` | `rgba(159,216,255,.55)` |
| day 白天 | `#eaf4ff` 正午白 | `rgba(234,244,255,.16)` | `rgba(234,244,255,.50)` |
| dusk 黄昏 | `#ffbe6b` 琥珀（默认档） | `rgba(255,190,107,.22)` | `rgba(255,190,107,.55)` |
| night 夜间 | `#b9c8ff` 月白 | `rgba(185,200,255,.20)` | `rgba(185,200,255,.55)` |

数值表落在 `ui/ControlPanel.ts` 顶部常量 `ACCENTS: Record<TimeId, {dim,line}>`，与 `content/times/` 的预设数据**无 import 关系**（依赖纪律），色值对齐由评审把关。

### 4.4 动效降级

```css
@media (prefers-reduced-motion: reduce) {
  .ui-anim, .seg-btn, .title-chip span { transition: none !important; animation: none !important; }
}
```

3D 场景过渡（§6）不受此开关影响——那是内容本身而非 UI 装饰动效。

### 4.5 玻璃件数量预算

同时存在的 backdrop-filter 元素 ≤3（chip + panel + 1 钮），hidden 态只有 1（ghost）。backdrop-filter 是合成器开销大户，**严禁给动画中的元素增减 blur 值**（§4.6）。

### 4.6 性能纪律（合成器友好）

1. 一切动画只动 `transform` / `opacity`（合成器属性）；`background-color` 等只出现在 hover/选中的**一次性状态切换**（180ms），不做连续动画。
2. 严禁动画 `backdrop-filter`、`box-shadow`、`width/height`。
3. 动画元素加 `will-change: transform` 仅在 `.ui-anim` 类上、动画结束移除（ControlPanel 统一管理），避免常驻层爆炸。
4. 面板收起/展开、隐藏/呼出、页签切换均为 transform + opacity 过渡。

## 5. 六.4 隐藏 / 呼出 UI（hiddenMode.ts，呼应一.4 L10）

### 5.1 入口与状态机

```
visible ──点击右上隐藏钮 / 按 H──▶ hiding ──▶ hidden
   ▲                                                      │
   └───────── 点击 ghost / 按 H / 触屏点 ghost ◀────────────┘
```

- **隐藏钮**（visible 态）：右上 36×36 圆形玻璃钮，眼睛图标；hover 时按钮轻微放大（scale 1.06）并浮现 11px 文字标签「隐藏界面」（`title` 属性 + 自绘 tooltip span，二选一取自绘——原生 title 有系统延迟）。
- **hiding**：`#ui-root` 内三个可见件（chip / panel / 隐藏钮）同时 `translateY(-8px) + opacity→0`，260ms ease-in；结束后 `visibility:hidden`（保留 DOM，呼出零重建成本）。**总时长 260ms，比一切场景过渡短**——观赏模式要"干脆"。
- **hidden 态唯一残留**：右上 30×30 圆形 **ghost 把手**，`opacity:.22`，eye-off 图标；hover/focus 升至 `.8`；触屏上恒为 `.22`（无 hover），但第一进入 hidden 态时播放一次"呼吸提示"（opacity .22↔.5 两个脉冲，共 2.4s，此后不再打扰）——解决触屏用户"UI 去哪了"的发现性问题。
- **showing**：反向 300ms ease-out；`visibility:hidden` 在动画首帧即解除。

### 5.2 键盘与触屏

`window.addEventListener('keydown')`：`KeyH` 切换（输入焦点在按钮上时同样生效）。触屏：ghost 把手 30px 略小于 44px 触控标准，外包一层 44×44 透明命中区（`padding` 实现）。

### 5.3 不持久化（决策 U5）

隐藏偏好、上次组合**均不写 localStorage**：十一.1 L151 要求"打开即玩、默认呈现黄昏海崖 C 型房车营地作为第一眼印象"，任何持久化都会破坏这条验收口径。每次刷新回到 `visible` + `applyState({scene:'seacliff', vehicle:'classC', time:'dusk', weather:'clear'})`（架构章 §5.1 组装流程原文）。

### 5.4 纯观赏模式的内容纯度

hidden 态下 DOM 可见件只有 30×30、22% 透明度的 ghost——满足一.4 L10"回到纯粹的观赏模式"；对比"完全没有残留"方案，取舍理由是触屏/不熟悉键位的用户必须永远有一条可发现（discoverable）的回归路径。

## 6. 六.5 切换过渡的实现（core/transition.ts，承接架构章 §5.3 与 D5/D6）

架构章 §5.3 已定四条切换路径的编排与时值；本章给出**过渡的几何/材质级实现机制**与参数，两章拼合后即为完整方案。

### 6.1 时间线总表（决策 D5 定值，常量集中在 core/transition.ts）

| 切换 | 总时长 | 机制 | 原文依据 |
|---|---|---|---|
| 时间 | 1500ms | 光照/天空/雾/语义通道**参数插值**，无重装配 | 四.5 L87"1~2 秒平滑光照过渡（交叉淡入淡出）" |
| 天气 | 1500ms | 粒子双集合交叉淡入淡出 + 材质 uniform 插值 + 风力指数趋近 | 五.6 L98"粒子与材质状态切换平滑过渡" |
| 场景 | 600ms | FadeSwap（§6.2）：旧组淡出 → 分帧构建 → 新组淡入 | 六.5-① L106"短暂淡入淡出" |
| 车型 | 600ms | FadeSwap（同 §6.2，作用对象为车型根组） | 六.5-① L106 |
| 离散装饰状态 | 中点切换 + 200ms 淡入 | blend≥0.5 一次性翻转，新增物 0.2s opacity 短淡入 | 架构章 §5.3 / D5 |

统一缓动：**smoothstep `t·t·(3−2t)`**——起停缓、中段快，匹配"不生硬跳变"（四.5 L87）；FadeSwap 的出/入分别用 easeInQuad / easeOutCubic（§6.2）。

### 6.2 场景/车型：FadeSwap——材质克隆透明度机制（决策 U2）

**问题**：淡出"旧场景组"最直觉的做法是遍历置 `material.opacity`，但架构章 §7#3 规定 `ToonMaterialFactory` 同参数材质**全局缓存共享**——直接改共享材质会把新场景（或底座、描边壳）一起改掉。**方案**：切换时对旧组做一次性材质克隆，动画只作用于克隆件。

```
FadeSwap(oldGroup, builder) 时间线（场景切换，总 600ms）：
t=0      FadeRig.prepare(oldGroup)：
           - 遍历收集 unique material 实例（含 OutlineSystem 反壳材质），逐个 material.clone()
           - 原材质→克隆件替换映射存入 group.userData.__fadeRig
           - 克隆件 transparent=true, depthWrite 保持 true（防旧场景变"透明壳"穿帮）
           - 若克隆件 uniforms 含共享 uniform 对象（WeatherMaterialSystem 的
             uWetness/uSnowCover…），把共享对象**按引用重新挂回**克隆件（见风险 §11-3）
           - oldGroup 全部 castShadow=false（防止旧场景淡出期间投影"鬼影"）
t=0–300  旧组克隆材质 opacity 1→0（easeInQuad）
t=150    Director 开始分帧构建新场景（架构章 §5.3"≤3 帧"），构建期间旧组仍在淡出
t=300    旧组从场景树移除；句柄反注册、SceneAnimation.dispose、assets 引用计数释放
         （架构章 §5.3 卸载清单）；克隆材质 dispose（材质仅自身，不触碰共享贴图——
         Material.dispose 不释放 texture，安全）
t=300–600 新组淡入：opacity 0→1（easeOutCubic）+ scale 0.96→1.0 + y: +0.35→0
           （"微缩陈列盒换上新展品"的落定感；淡入结束还原原生材质、恢复 castShadow）
```

- **克隆成本**：单场景 unique 材质约 30–80 个（含反壳），`Material.clone()` 每个微秒级，600ms 一次性成本可忽略；克隆件不复制几何体，显存零增长。
- **描边壳同步**：OutlineSystem 反壳若是网格子对象则天然被遍历覆盖；若为共享全局壳材质，同样进克隆映射（每个壳一份克隆，量级 ≤100，可接受）。
- **车型切换**：同一 FadeSwap，`oldGroup` 换成车型根组；新车型先按当前 `campAnchor` 对位（架构章 §5.3"轻微适配"）再淡入，且 `interiorLightHooks.applyInteriorLight` 以 blend=1 立即应用到当前时间档，避免"新车型灯先黑后亮"。
- **为什么不是"滑动过渡"**（六.5-①的另一选项）：平移滑动需要新旧两组同时在场（显存/Draw Call 翻倍）且会滑出底座暴露背景；交叉淡入+缩落既满足"短暂淡入淡出"原文措辞，又允许"淡出旧组"与"分帧构建"重叠（600ms 内完成装配，不撑长过渡）。

### 6.3 时间切换：光照参数插值（1500ms，机制归 TimeLightSystem，数值口径本章定）

TransitionController 生成一次性快照对 `(A = 当前插值状态, B = 新 TimePreset)`，此后每帧：

| 量 | 插值方式 | 备注 |
|---|---|---|
| 主光/环境光颜色 | `THREE.Color.lerpColors(a, b, t)`（工作空间线性 RGB） | 避免十六进制空间插值偏灰 |
| 主光强度/环境强度/雾基准 | 标量 lerp | |
| 日/月方向 | 方向向量归一化 lerp（夹角 <120° 时足够平滑）；≥120° 兜底四元数 slerp | 日↔月同灯共用（架构章 §7#5） |
| 天空渐变端点 uTop/uHorizon/uBottom、星空不透明度 | 颜色 lerp / 标量 lerp | render/sky.ts uniforms（架构章 §2） |
| 语义通道 lampPower/emberPower/smokePower/shopPower/interiorPower/interiorEmphasis | 标量 lerp | 下发 `scene.lightHooks.applyLighting(state, blend)` 与 `vehicle.interiorLightHooks.applyInteriorLight`（架构章 §3.2/§3.3 接口名照用） |
| 离散装饰状态（餐具出现/帆船已出海/送货小车/探照灯换岗…） | blend≥0.5 时单次翻转；新出现物 200ms opacity 淡入 | 由场景章在 `applyLighting` 内消费 blend，过渡器只保证"翻转恰好一次"（维护 per-transition 布尔） |
| 雾 | `fog = (scene.baseFog + time.fogBase插值) × weather.fogMul` 每帧重算 | AtmosphereSystem 单通道合成（架构章 D6），杜绝场景雾×天气雾双叠 |

时间过渡**可被再次 retarget**：新点击到来时以"当前插值中间值"为新 A、重新起 1500ms——连续快点四个时间档也是连续渐变，绝不跳变（§6.5）。

### 6.4 天气切换：粒子交叉淡入淡出 + 材质/风力趋近（1500ms）

- **粒子**：`ParticleSystem`（架构章 §4#3）保留双活动集合：旧集合全局倍率 `m(t) = 1−smoothstep(t)`，新集合 `m(t) = smoothstep(t)`；倍率同时作用于**发射率与已发射粒子的不透明度 uniform**（雨丝/雪花一起淡去，不出现"半空的雨瞬间消失"）。t=1 时旧集合整体回收进发射器池。粒子几何/发射参数（雨丝拉伸 quad、雪花软圆点 sprite 等造型）归粒子系统章/天气章，本章只锁定**交叉淡入淡出的曲线与时值**。
- **材质状态**：wetness / puddle / clothSag / snowCover / lineFade / cloudShadow 六分量随 smoothstep 插值写入共享 uniform（WeatherMaterialSystem 消费，架构章 §4#6）。夜雨"湿地彩色反光"（五-3 L95）无需专门过渡——它就是 wetness 与 lampPower 两个插值分量的乘积效应，时间与天气两条过渡各自插值、自然叠加。
- **风力**：`WindSystem.setWind(windMul × 阵风基准)` 不做阶跃，当前值按 `cur += (target−cur)·(1−e^(−3·dt))` 指数趋近（时间常数 ≈0.33s，1 秒内收敛 95%），布料统一受控（七.5 L116）。
- **光晕**：glowBoost（五-4 浓雾灯光扩散光晕）插值后乘入 `LightBreathSystem` 的 halo 不透明度（架构章 §4#4）。
- **云影**：cloudShadow 插值写入 AtmosphereSystem（五-2 云影缓慢移动的强度分量）。

### 6.5 连点与排队策略（UI 快速操作是常态，必须定义）

| 场景 | 策略 |
|---|---|
| 时间/天气过渡中再点 | **retarget**：以当前插值中间值为新起点重启 1500ms（§6.3），无排队、无跳变 |
| 场景/车型 FadeSwap 中再点 | 队列深度 1、**后到覆盖先到**：当前 600ms 走完（旧组已清、新组已入），随后立即发起"当前→最新目标"的又一次 FadeSwap。不为中间目标浪费一次装配 |
| 点当前已选中项 | AppState 同值守卫 → no-op |
| 面板视觉反馈 | 过渡进行中的维度行加分段容器 `data-busy` 态：容器描边呼吸一次（160ms），按钮不置灰（保持可点、可改主意） |

### 6.6 相机连续性（六.5-③，与 §7.5 合并陈述）

四类切换**全程不触碰相机**：相机状态（球坐标 + 目标点）唯一属主是 `core/controls.ts`（Engine 持有），TransitionController/Director 无任何 API 能读写它；场景/车型组透明度与缩落动画发生在模型组上，与相机解耦。用户在 600ms FadeSwap 中途继续拖拽也完全合法——所见即"一边换展品一边自由观看"。落实手段：controls 对外只暴露 `update(dt)` 与只读快照，`reset()` 仅存在于初始化；Director 源码评审清单中含"不得 import controls"一条（TASKS.md 勾验）。

const view = { theta: -0.62, phi: 1.13, radius: 12.5, target: new THREE.Vector3(0, 0.8, 0) }; // 当前值

默认机位（radius 12.5 / phi≈65° 仰角自地面 / theta -35°）是"黄昏海崖第一眼印象"的取景基准；模型主体落在画面中上部（§2.2 不遮挡保障①）。

### 7.2 鼠标（Pointer Events 统一实现，鼠标与触屏同一套代码）

- `pointerdown` → `canvas.setPointerCapture(e.pointerId)`，录入活动指针表；`pointermove/up/cancel` 更新/清除。
- 单指针拖拽 = 旋转：`goal.theta −= dx·0.0055; goal.phi −= dy·0.0045`（rad/px，含 phi 夹取）；灵敏度按 1080p 手感定值，可整体乘 `min(1, 720/视口宽)` 在小窗自动放缓。
- 滚轮 = 缩放（乘性，手感受倍率而非差值）：`goal.radius = clamp(goal.radius · e^(deltaY·0.0011), 5.5, 20)`，`wheel` 监听 `{passive:false}` + `preventDefault()`（页面本身不可滚动，仍防浏览器缩放手势）。

### 7.3 触屏

- 单指 = 旋转（同 §7.2 单指路径）。
- 双指 = **纯缩放**：`goal.radius = clamp(goal.radius · dPrev/dNow, …)`；双指中点位移不映射旋转（避免双指误旋）；第三指落下时忽略（指针表容量 2）。
- `canvas { touch-action: none }`（交给 Pointer Events，禁浏览器滚动/双击缩放）；`contextmenu` preventDefault（长按不弹菜单）；`pointercancel` 必须清空指针表——移动端来电/手势打断后手势状态不残留。
- UI 按钮触控目标 ≥44px（§2.2/§5.2），ghost 命中区 44px。

### 7.4 阻尼（帧率无关）

每帧 `k = 1 − e^(−9·dt)`，`view.x += (goal.x − view.x)·k`（x = theta/phi/radius 三分量）。9 s⁻¹ 阻尼系数的手感：拖拽跟手、松手 ~0.35s 缓停，无过冲无回弹（微缩模型观感要"稳"，决策不加惯性 fling）。渲染循环中 controls.update(dt) 排在架构章 §5.2 帧序 ①Clock 之后、render 之前。

### 7.5 连续性规则（六.5-③）

见 §6.6。补充验收方法：切换瞬间截取连续两帧画面，相机参数（theta/phi/radius/target）应逐位相等；四类切换各验一次。

### 7.6 画布自适应窗口（八.5 前半句）

```ts
// core/engine.ts（架构章 §2："renderer/scene/camera/渲染循环/resize（八.5 L124）"）
const applySize = () => {                                   // 合并到 rAF，一帧最多执行一次
  const w = container.clientWidth, h = container.clientHeight;
  renderer.setPixelRatio(Math.min(globalThis.devicePixelRatio || 1, 2)); // 架构章 §7#9：DPR ≤2
  renderer.setSize(w, h, false);                            // false：不改 CSS 尺寸，CSS 全权负责
  camera.aspect = w / h; camera.updateProjectionMatrix();
};
new ResizeObserver(applySize).observe(container);           // 容器级：布局变化也触发
globalThis.addEventListener('resize', applySize);
globalThis.addEventListener('orientationchange', applySize);
globalThis.visualViewport?.addEventListener('resize', applySize); // 移动端地址栏伸缩（iOS Safari）
```

CSS 侧：`html,body{height:100%;margin:0;overflow:hidden}`、`#app{position:fixed;inset:0}`、`canvas{width:100%;height:100%;display:block;touch-action:none}`。UI 各玻璃件的 safe-area 让位见 §2.2/§2.8。极小窗口（高 <560px）触发 §2.8 页签折叠，保证 UI 自身永不被裁切。

## 8. 状态流细化（core/state.ts / core/events.ts 的 UI 消费视图）

架构章 §2 只给了 state.ts 的职责（"AppState：四维当前值 + 变更事件"）；本章把 UI 所需的最小 API 面定死（如实现期签名有出入，按架构章卷尾注记回写 10-架构.md）：

```ts
// core/state.ts（本意为四维当前值容器，UI 消费视图）
type Dim = 'scene' | 'vehicle' | 'time' | 'weather';
class AppState {
  get(dim: Dim): string;                       // 当前 entry id
  snapshot(): Readonly<Record<Dim, string>>;   // 标题条一次性取四维
  set(dim: Dim, id: string): void;             // registry.get(id) 校验（未登记抛错并列可用 id，
                                               //   架构章 §3.1）；同值 no-op；成功后 emit
}
// core/events.ts：极简 on/off/emit，事件名 'state:change'，载荷 { dim, id, entry }
```

订阅方与职责边界（禁止越权）：

| 订阅方 | 响应 | 禁止 |

| TransitionController | 按维度路由四条路径（架构章 §5.3） | 直接改 DOM |
| hiddenMode | 无（独立于 state） | — |

## 11. 关键决策与待确认

### 11.1 本章决策（U1–U6，随 DESIGN.md 交用户确认）

- **U1｜控件形态与布局**：六.1 二选一取**分段按钮**；桌面为底部居中四行玻璃面板（约 420×262px），窄屏（<720px）自动折叠为「页签条+单组展开」；面板可手动收成页签条。理由：400 组合巡游需要四组常驻直达，同时用贴底+半透明+可收起满足"不遮挡、小巧克制"。
- **U2｜FadeSwap 材质克隆机制**：场景/车型淡入淡出通过**切换时一次性克隆组内材质**（含反壳壳材质）驱动 opacity，解决 ToonMaterialFactory 全局材质缓存（架构章 §7#3）与组级淡出的冲突；克隆件重挂共享 uniform 引用，结束即还原并 dispose。附 4% 缩落 + 0.35 单位下沉回位的"换展品"微动。
- **U3｜深色玻璃基线 + 时间档强调色**：玻璃取深色半透明（夜间/黄昏主导的组合里不抢"车内暖光"主角），强调色 --accent 随时间档四值联动（dawn 青 / day 白 / dusk 琥珀 / night 月白），作为"UI 与三渲二美术统一"（六.3）的色彩锚点。
- **U4｜自研轨道相机**：约 150 行 Pointer Events 实现（球坐标 + 指数阻尼 9s⁻¹ + 双指纯缩放），不引 three/examples 附加模块；换来手势统一、参数可控与"外部不可触"封闭性（连续性保障）。
- **U5｜不持久化任何 UI/组合状态**：无 localStorage，每次打开 = 默认组合 + UI 可见，严格满足十一.1"第一眼印象"验收口径。
- **U6｜连点语义**：时间/天气过渡随时 retarget（从当前插值中间值续变）；场景/车型队列深度 1、后到覆盖；选中项重复点击 no-op。快节奏巡游下永无跳变、永无死按钮。
