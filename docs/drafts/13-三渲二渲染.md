## 2. 卡通材质与渐变色阶（八.2 L121 上半；一.2 L8）

### 2.1 渲染管线总览

```
每帧：Engine.render
 ① 不透明 pass：地形/底座/道具/车辆/内饰 —— MeshToonMaterial 系（本文 §2.5 原型库）
 ② 描边壳 pass：OutlineSystem 反壳（renderOrder=1，§3.3）
 ③ 半透明 pass：车窗玻璃（renderOrder=10，§5.3）→ 天空背景板（renderOrder=-100 实为背景层）
 ④ 加性 pass：光晕 halo / 光斑贴花 / 湿地反光贴花 / 车流光条（renderOrder=20–30，depthWrite=false）
 ⑤ 粒子 pass：雨/雪/蒸汽等（ParticleSystem 的 GPU Points，§7.3-2）
 ⑥ 可选后期：UnrealBloomPass（仅夜间/浓雾启用，§7.4）
```

- 着色主体：**THREE.MeshToonMaterial + gradientMap（即 ramp 贴图）**，走 three 内建光照/阴影/雾管线——这是"卡通材质+渐变色阶"的零依赖落地，不引入任何着色库（八.1 L120 红线）。
- 色彩输出：`renderer.outputColorSpace = SRGBColorSpace`（three 近版默认），**`toneMapping = NoToneMapping`**。理由：色阶的本质是"色带平涂"，任何 tone mapping 都会把色带压出灰阶渐变、破坏"色彩柔和但富有层次"的平涂感；亮度全部由灯光强度与 ramp 锚色直接控制，不需要 HDR 装置。
- 亮度/光晕不用 bloom 兜底：所有"灯的亮"由 emissive 材质 + additive halo sprite 表达（§8），bloom 只是夜/雾的可选氛围增强（架构 §7-9），关闭后画面依然成立——这是降级阶梯的第一级（§7.4）。

### 2.2 色阶 ramp：纹理规格与生成器

ramp = 一张横向为 N·L（法线·光方向，0→1）、纵向恒定的小贴图，由 `ToonMaterialFactory` 内的 ramp 生成器现场绘制（Canvas，八.2 红线落点）：

- **规格**：256×4 px RGBA8（高度取 4 是规避个别驱动对 1px 纹理的采样怪癖）；`generateMipmaps=false`、`minFilter=magFilter=LinearFilter`——Linear 让色带边缘带约 1–2px 的自然抗锯齿，得到"硬但不锯齿"的动画色带（一.2"细腻但简洁"）；若要更锐的赛璐璐边缘可切 `NearestFilter`，作为工厂参数预留。
- **生成 API**：`buildRampTexture(steps: Array<{ t: number; shade: number }>): CanvasTexture`，按 key 缓存进 `SharedAssets`（架构 §4-10），全组合复用；`shade` 为 0..1 亮度系数，色相来自灯光与环境光（§2.3），ramp 本体保持**灰度**。
- **默认三段式**（主体物件标准档）：`steps = [{t:0, shade:0.34},{t:0.22, shade:0.34},{t:0.24, shade:0.62},{t:0.52, shade:0.62},{t:0.55, shade:1.0},{t:1, shade:1.0}]`——即深阴影带 / 阴影带 / 亮带，两条硬边界。量化档位即"渐变色阶"的"阶"。
- **档位变体**（工厂预置 5 种，全部同 API 生成）：

| ramp 档 | steps 概要 | 用于 |
|---|---|---|
| `ramp3` 三段（上文默认） | 0.34 / 0.62 / 1.0 | 车身、建筑主体、树冠、大件道具 |
| `ramp2` 两段 | 0.55 / 1.0 | 地面、混凝土、柏油、细碎小物 |
| `ramp4` 四段 | 0.28 / 0.5 / 0.74 / 1.0 | 车漆（多一档过渡，更"高精细"） |
| `rampSoft` 两段带宽过渡带 | 0.45→0.62 渐变 | 布料、纸张、野餐垫等软物 |
| `rampFar` 两段压平 | 0.72 / 1.0 | 远景剪影板、山脊（弱化对比防抢镜，配合 D1） |

- **关键机制**：ramp 只量化**直射光**；环境光（hemisphere）全额叠加不受量化。于是"暗部是什么颜色"由环境光决定——这正是日式二次元上色的经典分工，见 §2.3。

### 2.3 冷暖分离：环境光/方向光分工（一.2"色彩柔和但富有层次感"）

- 亮部色 = `方向光颜色 × ramp 亮带系数 × albedo`；暗部色 = `hemisphere 环境光色 × albedo`（ramp 暗带只压直射光，环境光原样保留）。
- 因此**阴影色相偏移不靠贴图、不靠补丁，靠灯光分工**：黄昏海崖 = 暖橙方向光（L22"日落金橙"）+ 蓝紫 hemisphere（L22"海面蓝紫渐变"）→ 亮部金橙、暗部蓝紫，即 3.1 L53 要求的"暖色车内灯光与冷色暮色海天的冷暖对比"的同一套机制。各档具体色值由时间章在 `GlobalLightParams`（架构 §3.4）里定，本章只锁定该分工结构。
- 光比纪律（一.5"安静治愈"、一.2"色彩柔和"）：暗带系数下限 0.34（§2.2 `ramp3`），全场最暗不低于 `#202438` 级别的深蓝灰而非黑——**任何组合不出现死黑阴影**，这是"治愈感"的渲染层底线。
- 日/月共用 1 盏方向光（架构 §2 L73）：夜间把方向光换成冷月光色、强度降档，ramp 机制不变，色带自动变冷——时间切换只改灯光参数（架构 §5.3"光照参数线性插值"），材质零改动。

### 2.4 增强项：RGB ramp 补丁、高光带、边缘光（onBeforeCompile，含降级路径）

三者为可选增强，统一经 `onBeforeCompile` 字符串补丁注入 MeshToonMaterial，**每个补丁都可独立关闭**；工厂用 `material.customProgramCacheKey()` 把补丁组合编进程序缓存 key，避免 three 误共享着色器程序（three 官方对 onBeforeCompile 的要求，实现时按锁定版本验证）。

| 补丁 | 注入点（思路） | 参数（uniform） | 用在哪 | 关闭后果 |
|---|---|---|---|---|
| **RGB ramp**：把内建 `getGradientIrradiance` 采样的 `.r` 通道改为 `.rgb` | 替换 1 行 GLSL | 无新增 | 需要强色相偏移阴影的场合（海崖海面、松林逆光剪影） | 退化为灰度 ramp + 环境光冷暖（§2.3），画面依然成立 |
| **高光带**：Blinn-Phong 硬阈值镜面 `step(uSpecLo, N·H)` 一档平涂 | fragment 尾部 additive | `uSpecColor/uSpecStrength/uSpecShininess/uSpecThreshold` | 车漆（`ramp4`）、玻璃、金属、湿地面（§5.5 `uWet` 抬高强度） | 无高光，纯色带——细碎小物默认关 |
| **边缘光 rim**：`pow(1-saturate(N·V), uRimPower)`，仅受光侧半量 | fragment 尾部 additive | `uRimColor/uRimStrength/uRimPower` | 树冠逆光（2.2 L85"金色光斑/逆光剪影"）、车漆夜间的天光反缘 | 无 rim，轮廓仍由描边承担，不塌 |

- 补丁与 three 版本耦合是本章头号技术风险：**脚手架阶段锁定 three 版本（≥0.160 的近期稳定版，以 pnpm 实装为准，记入 DEPENDENCIES.md）**，先写一条补丁冒烟用例（色带+高光+rim 同屏），再放量；补丁失败时工厂自动降级为纯内建 MeshToonMaterial（灰度 ramp），功能可用、风格略平——不允许因补丁阻塞交付。
- rim 与描边的分工：描边（§3）是"结构线"，rim 是"受光边缘的光"，两者并存；rim 强度全局克制（`uRimStrength ≤ 0.35`），避免与轮廓线混成双线（一.2"清晰轮廓线"优先）。

| 11 | `water` | 自定义 shader | 波光条 | 菲涅尔 | ✗ | 噪声 | 海面/溪流 | §8.2；1 块平面 + shader 时间相位，无顶点波动 |
| 12 | `cloth` | rampSoft | ✗ | ✗ | ✓ | 按需 | 天幕/遮阳棚/纱帘/晾晒物 | 顶点动画归 WindSystem（下凹 `uSag`，§5.5），本章只供原型与 uniform 挂点 |

- **emissiveLamp 是"灯"的唯一真理**（架构 §7-5"其余灯点全部 emissive+halo"）：灯不做真实光源，点亮感=自发光面+additive 光晕，这正是三渲二的惯常灯效语言，也是帧预算能守住的前提。
- 原型库新增流程：若某新内容物确实无原型可用 → 在本章评审追加原型行，禁止在内容模块里私搭 ShaderMaterial（依赖纪律 1：`render/` 不 import `content/`，架构 L38）。

### 2.6 色彩输出纪律（一.2/一.5）

- 饱和度上限：albedo 饱和度 ≤ S:80%（HSL 计），全场只允许"柔和但分层"；高饱和只出现在两处——黄昏天空渐变（§2.1 天空板）与 emissive 灯色（夜/雾的主角，2.4 L40）。
- 明度秩序（一.3"层次清晰"）：主体（车）> 近景道具 > 中景 > 远景剪影，靠 ramp 档位（`rampFar` 压平）与雾（D6 单通道）实现，不靠额外调色。
- 无渐变滥用：材质内部禁止平滑渐变（除 `rampSoft` 软物与天空板），渐变只属于天空与光晕——保持平涂的"模型感"。

### 2.7 阴影（配合四.1–4.2"长投影/短而清晰"）

- 单张 2048 shadow map，仅方向光投影（架构 §7-6）；shadow camera 正交范围≈底座对角（12×12 单位，1 单位=1m 的场景比例，§5.1），`bias≈-0.0005`、`normalBias≈0.03`（实现期微调，目标：色带边缘不被阴影噪声打碎）。
- **阴影静态化**：`renderer.shadowMap.autoUpdate=false`；仅在 ①时间过渡进行中（1500ms 内每帧 `needsUpdate=true`，实现长/短投影平滑移动）②场景/车型装配完成时 ③布料剧烈切换时置脏。稳态运行时阴影零重绘——布料微摆/树冠摇动幅度在 2–3px 内，阴影不跟随在微缩陈列盒观感下不可察觉，这是 §7 最大的单项 GPU 节省。
- 接收面：`groundTerrain/concrete/wood/vehicle` 接收阴影；`foliage` 冠层投+收，`emissiveLamp/glass/water/贴花/halo` 一律不参与阴影。

## 3. 描边方案选型（八.2 L121"反壳描边或后期描边均可"；一.2 L8"清晰的轮廓线"）

### 3.1 候选方案对比

| | A 反壳描边（inverted hull） | B 后期描边（深度+法线 Sobel） | C 折线边（EdgesGeometry） |
|---|---|---|---|
| 原理 | 复制几何、沿法线膨胀、只画背面 | 额外渲染法线+深度两张全屏 RT，全屏边缘检测 | 检测硬边画 LineSegments |
| 额外全屏 pass | 0 | 2（法线 prepass + 边缘合成） | 0 |
| 成本随 | 描边物体数（可用物体级开关裁剪） | 分辨率×全场景（不可物体级裁剪） | 边数 |
| 线宽 | 世界空间定宽→**近粗远细**，天然透视 | 屏幕均匀 | 屏幕均匀 |
| 曲面表现 | 好（沿法线连续） | 好 | 差（只出折线，有机形状断裂） |
| 多物体碎片 | 干净（逐物体独立） | 碎片小物易出噪点双线 | 中 |
| 逐物体控制粗细/颜色/开关 | 天然支持 | 只能全局或分区域 | 逐物体但表现差 |

### 3.2 结论：**反壳描边为主，后期描边仅留备选接口不实现**

理由（对应架构 §2 L72 与 §4-7 的既定注记，本节给出完整论证）：

1. **观感正确**：微缩陈列盒（一.1/一.3）的轮廓线应像模型厂手工勾线——世界空间定宽使近处粗、远处细，与实物模型的勾线透视一致；后期描边全线等宽，反而"数码感"。
2. **性能结构正确**：反壳无任何全屏 pass，成本线性于"开了描边的物体数"，可用物体级开关把预算花在刀刃上（§3.4）；后期 Sobel 的两张全屏 RT 在中端集显上是纯带宽税，且对本项目大量细碎道具（串灯泡、餐具、小旗）会产出噪点描边，一.2"清晰"反而受损。
3. **400 组合零分支**：反壳随物体走，材质/几何切换时壳自动跟随；后期 pass 需要为每个组合维护边缘检测阈值，否则雨/雾/夜间改写深度场景后双线闪烁——调参成本 ×400 组合，不可接受。
4. **依赖与可靠性**：反壳=一个 ShaderMaterial + 几何克隆，~150 行，无第三方；后期方案要 EffectComposer 多 pass 编排（虽 bloom 已引入 composer，但描边不该搭它的便车——bloom 可关，描边不可关，二者降级绑定是错的）。
5. **后期描边的真正优势本项目用不上**：Sobel 擅长"内结构线"（脸部衣褶），本项目无人物（一.6 L12）、几何程序化且偏简洁（§7.2 面数预算），反壳足够。

### 3.3 反壳实现细则（OutlineSystem 内部）

```ts
// render/outline.ts —— 挂接架构 §4-7
interface OutlineOptions {
  width: number;        // 世界单位，见 §3.4 档位表
  color?: string;       // 缺省取全局描边色 #2f2a33（§3.4）
  widthMode?: 'world' | 'screen';  // 默认 world（近粗远细）；screen 预留
}
OutlineSystem.enable(obj: Object3D, opts): void   // 克隆壳并随父级变换
OutlineSystem.disable(obj: Object3D): void        // 摘壳；材质工厂也接受 noOutline 标记（架构 §7-4）
```

- **壳几何**：直接引用本体 geometry（不重建顶点数据，共享 `SharedAssets` 缓存），壳 mesh 挂在本体同父级、复制本地变换；壳材质 = `ShaderMaterial { side: BackSide, 顶点: pos + normal * uWidth, depthWrite:true, depthTest:true }`，`renderOrder=1`（不透明体之后画）。
- **顶点偏移取世界空间法线 × uWidth**：相机推拉时线宽随透视自然变化（§3.1-4）；不做屏幕空间恒宽（那是后期方案的观感）。
- **硬边处理**（反壳经典缺陷：低模硬边处壳会裂缝/过细）：`geom/parts/` 部件库铁律——需要描边的部件，其硬边（箱体棱、桌沿）在工厂里按面拆分顶点法线（`toNonIndexed` 后按面 `computeVertexNormals`），平滑曲面（车壳用 Lathe/Extrude/Sphere 段）保持共享平滑法线；描边宽度上限 0.06 单位，超出即视觉脏。
- **实例化成对**（架构 §7-4）：本体是 `InstancedMesh` 时，壳同样建为 `InstancedMesh` 并共享同一份实例矩阵 buffer——每个实例化组恒定 2 个 draw call（本体+壳），§6.3 预算按此计。
- **不描边即不建壳**：`noOutline` 物体零成本；`enable/disable` 支持运行时切换（如玻璃窗框描边、玻璃本体不描）。
- **壳与色阶的渲染顺序**：壳 renderOrder=1 在本体后、透明体前；壳不写颜色到透明混合（不透明纯色），与加性 halo（renderOrder≥20）天然分层（§6.5）。

### 3.4 描边分级与颜色（统一与差异的"统一"侧）

**全局描边色**：不用纯黑。默认 `#2f2a33`（深暖灰紫，兼容金橙/蓝紫双基调）；暖色主导物体可取 `#3a2e2a`，冷色主导取 `#2a3040`——由材质工厂按 albedo 色相自动选择三选一（规则固定，非逐物体手调）。六.3 UI 细描边取同一色系，保证 UI 与画面的三渲二统一感。

**宽度档位**（场景比例 1 单位=1m，底座 10×10，§5.1；1080p、常态观察距离 ~12 单位下约 2–3px）：

| 档 | 宽度（世界单位） | 适用 |
|---|---|---|
| 车辆级 | 0.020–0.025 | 车身外壳、拖挂箱体（视觉主角，一.3 构图中心） |
| 建筑级 | 0.030–0.050 | 掩体/便利店/雨棚柱/瞭望塔/灯塔/集装箱 |
| 道具级 | 0.010–0.016 | 桌椅/护栏/油桶/烤炉/行李箱 |
| 小件级 | 0.008 | 水瓢/餐具/警示牌（可选，过多则关） |
| 底座级 | 0.050 | 底座外缘一圈（"陈列盒"边线，一.3） |
| 关闭 | — | 远景剪影板（D1，它本身就是轮廓）、玻璃本体、emissive 灯面、halo/粒子/贴花、内饰组（隔着玻璃描边会脏，§5.3）、水面 |

### 3.5 后期描边的备选保留

`OutlineSystem` 保留 `mode: 'hull' | 'post'` 枚举位与接口形状（架构 §4-7 已注记"后期描边备选"），本章明确：**实现阶段只交付 hull**；仅当实现中出现反壳不可行的物体类别（预期风险：alpha 裁切的植被叶片——本项目植被用实体低模锥/球，预判不会触发），才评审是否局部启用 post 模式，并回写架构与本章。

## 4. Canvas/SVG 程序化贴图策略（八.2 L121 末句）

### 4.1 基础设施（tex/canvasTex.ts，架构 §2 L116）

```ts
createCanvasTexture(key: string, w: number, h: number,
  draw: (ctx: CanvasRenderingContext2D) => void,
  opts?: { srgb?: boolean; mipmaps?: boolean; anisotropy?: number; wrap?: WrapMode }
): CanvasTexture   // 命中 key 直接返回缓存；未命中现场绘制
// 引用计数经 SharedAssets.acquire/release：场景卸载时计数归零才真正 dispose（架构 §5.3 卸载路径）
```

- 默认 `colorSpace=SRGBColorSpace`、`anisotropy=min(4, renderer.capabilities.getMaxAnisotropy())`（集显友好，地面掠射角是主要受益者）；halo/噪声小图 `mipmaps=false`。
- **全局常驻层**：ramp×5、噪声库×4（value-noise/fbm/颗粒/锈斑）、木纹、halo 径向渐变——注册后引用计数永不清零，跨 400 组合零重建。
- **场景层**：各场景地面图/招牌/划线随场景装配 acquire、卸载 release（架构 §5.3），切换两次后同类贴图命中缓存。

### 4.2 三类生成策略与选用准则

| 类 | 手段 | 适用 | 要点 |
|---|---|---|---|
| **图案绘制类** | Canvas 2D 路径/文字 | 招牌灯箱、路牌/出口指示牌、手写警示牌（2.3 L33）、B 型手绘贴纸（3.4 L67）、车牌、烧烤炉贴纸、售货机货道 | 文字用**系统字体栈**（八.1 不联网）；"手写感"=圆头粗描边+逐字符 ±4° 旋转+基线抖动，不用手写字体（无网络）；文案集中 `tex/signageTexts.ts` 常量表，便于九.3 复盘逐条核对 |
| **程序噪声类** | 自写 value noise / fbm（~60 行，无依赖） | 木纹（正弦条纹+噪声扰动）、沥青颗粒、混凝土污渍、苔藓/草地色斑、锈迹蒙版、星空点阵、海面噪声 | 噪声以内容 id 为种子（`shared/rng.ts`，架构 L125），同组合每次生成完全一致 |
| **矢量线稿类** | SVG 字符串 → data URI → Image → Canvas | 交通标志（箭头/限速/出口号）、充电桩/加油机符号、卫星锅面板刻线 | 仅用于本质是矢量符号的图形；SVG 光栅化是异步 load → `tex/` 提供 `preloadAll(): Promise` 在场景装配前 `await`（架构 §5.1 装配流程内完成，不进入帧循环） |

**准则**：默认 Canvas 2D（同步、可控、无异步风险）；只有矢量符号才用 SVG。两者都是"程序化生成"，满足八.2 字面。

| 场景地面（草坪/碎石/硬化地/柏油×划线层） | 512² | 4 | ≈5.6 MB |
| 车身涂装/贴纸层 | 512×256 | ~8（5 车型+变体） | ≈4.2 MB |
| 招牌/灯箱/路牌/警示牌 | 256²/256×128 | ~10 | ≈1.5 MB |

| 噪声库（共享） | 256² | 4 | ≈1.1 MB |

### 4.4 与色阶的配合：中值原则（一.2"材质表现干净"）

- **明暗不烘进贴图**：图案类贴图以 0.85–1.0 亮度的"近白中值"绘制（图案=色相/图形成分，无自带阴影），全画面的明暗只来自 ramp×灯光——贴图自带明暗会与色阶打架，产生"脏"感，这是"材质干净"的技术含义。
- 例外即语义图形成分：划线、招牌文字、警示条纹——它们是"内容"不是"光影"。
- 噪声类贴图幅度纪律：混凝土/沥青亮度扰动 ≤8%，锈迹对比度低且色相贴着基底色（一.5"末世也要画得干净"）。

### 4.5 UV 规范与内容红线

- UV：程序化几何出厂自带可用 UV（Box/Sphere/Cylinder/Lathe/Extrude），部件库铁律：需要贴图的部件在工厂内排好 UV（集装箱六面共用 0–1 区、车身侧面用 512×256 横向展开区），贴图一律 `ClampToEdge` 或显式 `Repeat`（tile 类），禁止依赖默认 UV 碰运气。
- **不要人物红线（一.6 L12）**：`tex/` 全部生成函数禁止出现人物/人脸/人形剪影元素——贴纸主题限定 山/海/浪/太阳/字母数字/箭头，警示牌用符号与文字，城市剪影（2.3 L33）仅建筑轮廓。与 `geom/parts/` 的"禁止人形几何"铁律（架构 L113–114）构成几何+贴图双层封禁；TASKS.md 勾验时逐贴图函数过目。

### 4.6 贴图不动原则

运行期**零 canvas 重绘、零纹理上传**：需要"动"的图（波光、光斑摇曳、云影、湿地反光、车流）全部是**静态贴图 + shader 的 uv 偏移/时间相位**（§8）；划线若隐若现是 `uLineFade` uniform 乘 alpha（§5.5），不重绘。唯一例外：天空渐变随时间档切换时重绘 512² canvas 一次（1500ms 过渡的起点/终点各一次，不在每帧路径上）。

## 5. 色阶与描边在四场景 × 五车型上的统一与差异（八.3 与一.2/一.3 交叉要求）

### 5.1 统一规则（400 组合的不变量）

1. **同一套机制**：ramp 生成器（§2.2）、12 类材质原型（§2.5）、反壳系统与三档描边色（§3.4）、冷暖灯光分工（§2.3）全组合唯一。
2. **同一套比例**：1 单位=1m；底座 10×10；车长 1.9–2.4 单位（C 型 2.0 / A 型 2.4 / 皮卡 2.2 / B 型 1.9 / 拖挂组合 4.6 含牵引间距，D4）；描边档位表（§3.4）按此标定。
3. **同一套秩序**：明度秩序（§2.6）、无死黑底线（§2.3）、中值贴图（§4.4）、无渐变滥用（§2.6）。
4. **底座形式统一**（一.3 L9）：几何由 BaseAssembler 统一（架构 L68），本章锁定其材质配方——顶面=`groundTerrain`（贴 ramp2 + 场景地面图），边缘=45° 倒角环带涂 `edgeColor`（`matteProp` 无贴图），外缘描边 0.05 档；`ScenePalette.baseStyle` 只携带通道引用与边缘样式枚举（`'bevelBand'|'paintStrip'`），不含任何材质代码。

| 地面贴图 | 草坪+裸土斑 | 碎石+苔藓斑 | 硬化地+裂纹（低对比） | 柏油+划线层（`uLineFade`） |

| 专属材质/动效 | `water` 海面波光（§8.2）、晚霞天空板 | `foliage` 层叠树冠、光斑贴花摇曳（§8.3）、`water` 溪流 | `metal` 锈迹蒙版、火光/荧光 emissive、探照灯光束锥（§8.4） | 灯箱/售货机 emissive（shopPower，D8）、车流光条（§8.5）、湿地反光贴花（§5.5） |
| 雾基底 `baseFog` | 0.10 | 0.30（晨雾，D6） | 0.08 | 0.06 |

### 5.3 五车型差异（`PaintSpec` / `WindowSpec` 数据化；3.6 L77 落实）

- **车漆**：五车型共用原型 `paintCar`，差异只在 `PaintSpec` 数据——`{ baseColor, stripeSpec?, textureKeys?, weathering? }`（架构 L284；`weathering` 默认关，架构 Q2）。涂装贴图（条纹/贴纸层）由 `tex/` 出图；**新车型永远不新增材质原型**，渲染层对车型数无感知。
- **可透视窗**：`WindowSpec`（架构 L285）→ 原型 `glass`：`transparent:true, opacity≈0.32, depthWrite:false, renderOrder=10`，白天高光斜条（`uSpecThreshold≈0.93` 一条固定斜带，动画感"玻璃斜光"）；**夜间 opacity 随 `interiorPower` 降至 0.22**——车内暖光透出增强（四.4 L86"车内暖光更突出"、3.1 L53 冷暖对比），且室内 emissive 物件（小夜灯/灯带）透过玻璃直接可见。
- **内饰可见性**：内饰组（`VehicleInterior.group`）默认 `noOutline`（隔玻璃描边必脏）+ 不接收方向光阴影（避免玻璃后光斑错乱）；内饰照亮不占点光——内饰灯=emissive+玻璃内侧 emissive 染色（`interiorGlow` 通道染色窗内可见面），保证 0 额外光照成本。
- **车内暖光点光**：夜间从点光池（§2.7，架构 ≤2 点光预算）申请 1 盏暖色点光（`color#ffb26e, distance≈3.5, decay=2`）照亮车身周围地面/天幕内侧——"深夜中的温暖焦点"（四.4 L86）的落地手段；另一盏留给场景钩子（篝火/探照灯），Director 按优先级仲裁。
- **描边**：五车型统一车辆档（0.020–0.025）+ 全局描边色自动选色（§3.4）；拖挂组合（D4）皮卡与拖挂各自成壳。
- **差异强制点**（3.x"明显差异"的渲染侧核对项，交 TASKS.md）：C 型暖白+饰条 / A 型贯通侧窗长玻璃带（玻璃面积最大）/ 拖挂白色流线壳（`ramp4` 高光带最亮）/ B 型双色车身+贴纸层 / 越野哑光军绿（`paintCar` 关高光带变体，参数化实现，非新原型）。

### 5.4 时间维度对色阶的作用机制（四.1–4.5 L83–87）

| 时间档要求（原文） | 渲染机制 | 数值来源 |
|---|---|---|
| 清晨：低角度青金晨光、长投影 | 方向光低仰角→ramp 暗带面积自动拉大=长投影；光色青金 | `TimePreset.lighting`（时间章） |
| 白天：短而清晰阴影、色彩干净饱和 | 高仰角→暗带收窄；hemisphere 提亮保饱和 | 同上 |
| 黄昏：金橙/蓝紫、蓝调时刻、冷暖对比 | §2.3 分工的最强档（暖 dir + 蓝紫 hemi） | 同上 |
| 夜间：深蓝紫环境、月光主导、灯光全亮带光晕 | 方向光换月色低强度；emissive×`lampPower=1` + halo 淡入（§8）；点光池启用 | 同上 |
| 1~2s 平滑过渡（四.5 L87） | 灯光/天空/ramp 无关参数线性插值（架构 §5.3），ramp 贴图本身不换 | `transitionMs=1500`（架构 D5） |

ramp 贴图与材质**在时间切换中零替换**——变的只有灯光与通道值，这是"切换不生硬"的结构保证。

### 5.5 天气维度对材质的作用（五.2–5.6 L94–98）

`WeatherMaterialSystem`（架构 §4-6）把天气参数写入**全局共享 uniform 单例**，工厂经 `onBeforeCompile` 把同一 uniform 对象按引用注入相关原型（改一处、全场生效，无逐材质遍历）：

| uniform | 语义（原文出处） | 作用的原型与方式 |
|---|---|---|
| `uWet` | 地面湿润反光、夜间彩色反光（五.3 L95） | `groundTerrain/asphalt`：高光带强度 ×(1+3uWet)、albedo 加深 10%、色带并档（ramp2→近似 ramp 单档压平=湿面"镜面平涂"感）；**彩色反光**=灯点倒影贴花（`ReflectionDecal`，§8.6）opacity∝`uWet×lampPower×nightFactor` |
| `uPuddle` | 水洼涟漪（五.3） | 地面贴图上的预烘水洼 alpha 区 + `water` 原型低配版（涟漪=噪声 uv 扰动） |
| `uSag` | 天幕/遮阳棚积水下凹（五.3） | `cloth` 顶点：`y -= uSag * f(顶点距骨架距离)`，与 WindSystem 摆动叠加（架构 D3，Wind 持顶点着色权） |
| `uSnow` | 顶面积雪：屋顶/天幕/树枝/护栏/桌椅/地面薄雪（五.5 L97） | 通用**法线朝上遮罩**：`snowMask = smoothstep(0.55, 0.8, normal.y)`，`albedo = mix(albedo, snowWhite#eef2f6, uSnow*snowMask)`——一行语义覆盖原文枚举的全部"朝上面"，`WeatherSurface.kind='roofTop'` 即"任何朝上硬表面"（树冠、护栏顶同理，不改架构枚举）；地面（kind='ground'）整面 mix |
| `uLineFade` | 车位划线若隐若现（五.5） | 划线层 alpha ×(1−uLineFade×0.85)（服务区专用，kind='linePaint'） |
| `uCloudShadow` | 云影地面缓慢移动（五.2 L94） | 底座上空 1 张半透明噪声大 quad（黑色、NormalBlending），uv 随时间平移，opacity=uCloudShadow×0.25，1 draw call |
| glowBoost | 浓雾/夜间光晕扩散（五.4 L96、五.6） | halo sprite 尺寸×(1+glowBoost)、bloom 强度 lerp（§7.4）；雾密度走 AtmosphereSystem 单通道（D6），本章不重复造雾 |

所有天气量经 1500ms 过渡插值（架构 D5）后写入 uniform——材质零重建，满足五.6"平滑过渡"。

### 5.6 400 组合零分支的保证（结论）

组合 = ①场景通道色/贴图（场景数据）×②时间灯光与通道（时间数据）×③天气 uniform（天气数据），三者在 `ToonMaterialFactory` 产出的**同一批材质实例**上交汇；渲染层不存在任何 `if (scene==='seacliff')`。架构 L44/L77 的"新增不改核心渲染"由此在渲染侧成立。

## 6. 实例化与 Draw Call 控制（八.3 L122 前半）

### 6.1 InstancedGroup 规范（geom/instanced.ts）

```ts
group = new InstancedGroup(geometry, material, { capacity: 64, withShell: true });
group.add(matrix, optionalColor);   // 装配期逐实例放入；finalize() 后不可再增
group.setMatrixAt / setColorAt      // instanceColor 用于同种个体 ±5% 明度/色相微差（防"复印感"，一.2"富有层次"）
```

- `withShell:true` 时成对创建壳 `InstancedMesh`（§3.3），共享实例矩阵 buffer——恒定 2 draw call/组。
- 判据（架构 §7-2"部件库 review 硬标准"）：**同类≥3 个必实例化**；`instanceColor` 只做明度扰动不做色相大改（色相属通道语义）。

### 6.2 实例化/合并/独立 三选一决策树 + 场景实例化清单

```
同类重复 ≥3 且同材质？ ──是──▶ InstancedGroup（含壳）
        │否

动态/可开关/需独立动效 ──▶ 独立 Mesh（车辆、灯、可交互件）
```

### 6.5 renderOrder 与透明排序（防闪烁）

| 层 | renderOrder | depthWrite |
|---|---|---|
| 天空板 | -100（背景） | ✓ |
| 不透明本体 | 0 | ✓ |
| 描边壳 | 1 | ✓ |
| 玻璃 | 10 | ✗ |
| halo/光斑/反光/云影 | 20 | ✗ |

同一 renderOrder 内的加性元素之间顺序无关（加法可交换）——这是把所有 additive 统一压到 20/30 的原因，透明排序问题被设计掉，而非逐帧排序解决。

## 7. 中端笔记本 60fps：性能预算与达标手段（八.3 L122 后半）

### 7.1 帧预算账本（16.6ms @ 60fps）

| 预算项 | 上限 | 说明 |
|---|---|---|
| CPU 逻辑（Clock/过渡插值/系统 uniform/调度器） | 3.0 ms | 全部为"写少量 uniform/矩阵"，无逐顶点 CPU（架构 §7-7） |
| 渲染提交（≤200 DC 的 JS 开销） | 2.5 ms | 集显下 draw call 开销显著，DC 预算是硬约束的原因 |
| GPU 帧时间 | ≤14 ms（与 CPU 重叠） | 1080p、Iris Xe / GTX 1650 档；主体 pass 便宜（toon=1 张阴影采样+色带） |
| 阴影重绘 | 稳态 0 | §2.7 静态化；过渡期 1.5s 内每帧重绘可接受 |

### 7.2 资源预算

- **三角形**：本体 ≤170k（车辆 ≤45k、场景 ≤125k）+ 描边壳 ≤70k（仅描边物 duplicat）+ 粒子/天空 ≤10k → **全场 ≤250k**。部件规范：松树 ≤900 tri（干+3 层冠）、礁石 ≤120、桌椅 ≤300、灯泡 ≤48、集装箱 ≤100、车身壳 ≤18k、内饰 ≤12k/车。程序化建模在工厂里写死分段数（如 Sphere 分段 12×8 起步按需降），防止实现期随手拉高。
- **贴图显存** ≤48 MB（实测估算 ≈17 MB，§4.3）。
- **像素**：主 pass 1×+少量加性 overdraw（halo 总面积 ≤ 屏 15%）；无默认全屏后处理（bloom 条件启用）。

### 7.3 十项达标手段（渲染层细则，承接架构 §7 表并具体化）

| # | 手段 | 落点与参数 | 预期收益（定性） |
|---|---|---|---|
| 1 | 描边分级关闭 | §3.4 表；灯面/水/贴花/内饰/远景强制关 | DC 与三角形近半 |
| 2 | 粒子 GPU 化 | 雨 ≤600 点 / 雪 ≤400 / 尘 ≤80 / 火星 ≤60 / 蒸汽 ≤40，全部单 DC Points | 粒子成本 ≈0 |
| 3 | 阴影静态化 | §2.7 `autoUpdate=false` | 稳态省 1 次场景深度 pass |
| 4 | 点光 ≤2 | 架构 §7-5；其余灯=emissive+halo | 着色器光照循环恒定 |

### 7.4 降级阶梯（全自动、无 UI，一.4 L10）

```
L0 全效果（bloom 夜/雾启用，pixelRatio ≤1.75）
L1 关 bloom（halo 仍在，画面成立——§2.1 设计保证）
L2 pixelRatio → 1.25
L3 pixelRatio → 1.0 + 远距离 halo 剔除
```

- 触发：启动后 4s 滑窗均帧 <50 → 降一档；20s 时复查一次最多再降一档。**只降不升、全程静默**（一.4 无杂乱元素）；用户无感知差异的降级不值得 UI。
- bloom 启用条件：`time==='night' || weather==='fog'`，强度随 `glowBoost` lerp（五.4/五.6 L96/L98"扩散光晕"），参数基线 `strength 0.35 / radius 0.6 / threshold 0.85`。

### 7.5 验收测量方法（回应架构 L536 遗留 Q6 的本章部分）

- 工具：内置 FPS 计（dev 面板，含 1% low）+ Chrome DevTools Performance；**仅内置浏览器调试（九.2 L129），不碰系统浏览器**。

- **未实测声明**：工程未搭建，以上均为设计预算；本节方法在实现阶段执行，结果记入 TASKS.md，若某分项实测超预算，按 §7.3 手段逐项回收（先 1→2→3）。

## 8. 材质级动效的实现方式（七.1–7.4 中渲染层承担的部分）

归属总则（架构 D3/§4 归属裁定）：**布料归 WindSystem、粒子归 ParticleSystem、灯的呼吸/闪烁/旋转归 LightBreathSystem（RhythmClock 统一节奏，七.5 L116）**；场景私有编排归 `SceneAnimation`。本章只定义"动的是材质/着色的哪些项、用什么机制"：

| 动效条目（原文出处） | 机制 | 实现方式 | CPU 每帧成本 |
|---|---|---|---|
| 海面波光粼粼（2.1 L22、七.1 L112） | `water` 原型 shader | 两层噪声阈值高光带，`uv += t*speed` 反向滚动 + 菲涅尔混天空色；1 平面 1 DC | 2 个 uniform |

| 溪水流光/落叶漂流（七.2） | `water` shader / 粒子 | 流光=uv 滚动同海面；落叶=EmitterSpec 'leaf'（归 ParticleSystem） | uniform |
| 灯塔光束旋转（七.1） | 光束锥 + LampHandle 'rotate' | 锥体=ConeGeometry 开口端 + additive 渐隐 alpha 贴图（canvas 径向），旋转由 LightBreath 驱动 | 1 矩阵 |
| 探照灯扫动/警示红灯旋转（七.3） | 同上 'rotate' 模式 + 场景编排扫动轨迹 | 光束锥复用；红灯=emissive 球+halo 旋转（billboard halo 不转，转的是灯体与光斑） | 少量矩阵 |
| 灯箱循环微闪/售货机灯带常亮（七.4） | `emissiveLamp` × LightBreath 'blink'/'steady' | 功率通道=shopPower（D8）；微闪=breath 低幅度高频 | uniform |
| 车流灯光流动（2.4 L40、七.4） | 车流光条 InstancedGroup(8) | 光条=细长 additive quad，SceneAnimation 沿公路样条移动+到端头循环 | 8 矩阵 |
