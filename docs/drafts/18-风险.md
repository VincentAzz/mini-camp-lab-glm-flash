## 1. 性能风险（60fps，八.3 L122）

### R1｜onBeforeCompile 补丁与 three 版本耦合【高】
- **描述**：渲染章 §2.4 的 RGB ramp / 高光带 / rim 三个补丁、WindSystem 布料位移、天气共享 uniform 注入全部依赖替换 three 内建着色器字符串；three 升级可能改名/重排 chunk 导致补丁静默失效或报错（渲染章 R1）。
- **影响**：三渲二风格核心（色阶、阴影色相、布料）全面受损。
- **缓解**：①版本锁定 ≥0.160 近期稳定 + lockfile 提交（16 章 §2.3）；②T06 补丁冒烟用例先行于一切内容开发；③每个补丁可独立关闭，全关退化为纯内建 MeshToonMaterial + 灰度 ramp + 冷暖灯光分工，画面依然成立（渲染章 §2.4 降级路径）；④实现期不随手升级 three，升级 = 重跑冒烟 + 回写 DEPENDENCIES.md。
- **残余**：three 内部 chunk 布局仍可能在中途小版本变化——以锁定版本消除。

### R2｜Draw Call / 材质数超预算【中】
- **描述**：全组合 ≤200 DC、≤28 材质实例是设计预算（架构 §7-8、渲染章 §6.3/§6.4），未实测；最重组合（拖挂+场景+夜+雨+halo+粒子）可能破线；场景章各场景自估 115–150 DC、车型章各车 28–38 DC，均为纸面值（12 章 §11-11 遗留）。
- **影响**：中端集显掉帧，60fps 不达。
- **缓解**：①Engine dev 计数器（T02）从第一个部件起常显 DC/材质数，超预算部件在 geom/parts 层当场合并（渲染章 §7.3-8）；②描边分级关闭（灯面/水/贴花/内饰/远景强制 noOutline，渲染章 §7.3-1）；③同类 ≥3 必实例化 + withShell 成对（§6.1）；④T44 用实测值回填 12/13 章预算表，破线按「先关 bloom → 降 DPR → 远距 halo 剔除」降级阶梯回收（§7.4）。
- **残余**：最重组合若仍超线，接受该组合 pixelRatio 降档（观感轻微变软，功能无损）。

### R3｜halo/贴花 overdraw 与像素填充率【中】
- **描述**：串灯 14 泡 + 夜/雾 halo 放大（glowBoost ×1.8）、湿地反光条、云影 quad、车流光条叠加在大面积地面上，加性混合 overdraw 可能成集显瓶颈（渲染章 R4）。
- **影响**：夜间/浓雾（恰恰是氛围主力档）帧率下降。
- **缓解**：halo ≤64²、屏幕占比 ≤15% 预算、op<0.02 自动隐藏、L3 远距 halo 剔除、bloom 仅夜/雾启用且可关（渲染章 §7.3-2/§7.4、时间天气章 §6）；T44 专项测夜间浓雾组合。
- **残余**：夜间组合集显上比白天慢属预期，以 ≥55fps 达标线衡量。

### R4｜阴影静态化的边界情况【低】
- **描述**：阴影 autoUpdate=false 稳态零重绘（渲染章 §2.7），但布料剧烈切换、场景切换、时间过渡期需置脏；漏置脏会出现影子与物体不符。
- **影响**：影子"鬼影"级穿帮（小概率、易察觉）。
- **缓解**：置脏时机收敛为三处（过渡进行中/装配完成/布料剧变），封装为引擎 API 而非散落调用；T32/T40 端到端验收含影子核对。
- **残余**：布料微摆（2–3px）阴影不跟随，为已接受的观感取舍（微缩陈列盒下不可察觉，渲染章 §2.7 声明）。

## 2. 三渲二观感达成度风险（一.2 L8）

### R5｜观感"不到三渲二"（像普通 3D 或像纯色积木）【高·主观】
- **描述**：三渲二观感 = 卡通材质 + 渐变色阶 + 清晰描边 + 冷暖分工 + 材质干净（一.2 逐词），其中任何一环弱化都会让整体"掉档"；且审美达标与否主观，参数表全部为纸面初值（场景章 §8.4-5、时间天气章 B4）。
- **影响**：核心验收（十一.3「三渲二、日式二次元」）不达。
- **缓解**：①机制上锁死分工——暗部色相由 hemisphere 决定、ramp 只量化直射光（渲染章 §2.3），无死黑底线（暗带 ≥0.34）；②描边近粗远细反壳（§3）保"模型勾线感"；③T45 以默认组合「海崖·C型·黄昏·晴朗」为观感锚点先定调，再横向推广到其余组合；④T43 全局调参轮 + T46 组合巡游逐格观感抽查；⑤全部动效/光照参数表在 TASKS.md 复盘区留"可整体微调"条目（场景章 U4）。
- **残余**：观感上限依赖实现期迭代轮数；已在阶段计划中给 T43/T45 两轮专门调参。

### R6｜反壳描边的硬边裂缝与崖体破面【中】
- **描述**：反壳在低模硬边处会裂缝/过细（渲染章 R2）；崖体 Extrude 侧壁倒角处反壳易破面，需"仅顶缘描边"或顶缘 Tube 描边替代（场景章 §8.4-1）。
- **影响**：轮廓线脏（一.2"清晰轮廓线"受损）。
- **缓解**：部件库法线规范（硬边拆分顶点法线、曲面共享平滑法线，渲染章 §3.3）+ 描边宽度上限 0.06；崖体等特例采用顶缘 Tube 描边方案；部件逐个目检进 TASKS.md（T16/T18 验收项）；OutlineSystem 保留 post 模式接口仅备不启（§3.5）。
- **残余**：个别异形件可能需逐个手调，已列入实现期验证点。

### R7｜描边壳与透明体的排序穿帮【低】
- **描述**：renderOrder 分层（天空 -100 / 本体 0 / 壳 1 / 玻璃 10 / halo 20 / 粒子 30，渲染章 §6.5）依赖严格遵守；城市剪影/雾板/灯箱的排序可能出现错帧（场景章 §8.4-4）。
- **缓解**：渲染顺序在工厂与 BaseAssembler 内统一设置而非内容模块自定；T46 巡游含"夜+雾"排序专项抽查。
- **残余**：个别叠加场景（避难所双剪影板+雾）需实现期微调 renderOrder。

## 3. 纯程序化建模表现力上限（八.2 L121）

### R8｜无 DCC 下复杂形体的精度上限【中】
- **描述**：严禁 Blender（八.2），全靠基本体/Lathe/Extrude/Tube/实例化；流线拖挂"罐头火腿"壳（分瓣拼装）、C 型凸头、帆船、灯塔等形体在代码建模下精度有天花板；"高精细建模"（一.2）与面数预算（≤250k tri）双重约束。
- **影响**：个别形体观感粗糙或面数超标。
- **缓解**：①四大手法库（roundedBox/profileExtrude 侧影开洞/分面拼装/Lathe，车型章 §2.2）+ 20 个 vehicleKit 部件工厂复用（§2.7），把复杂度摊到参数化部件；②分段数在工厂写死防止随手拉高（渲染章 §7.2）；③"高精细"以细节密度而非网格精度实现（内饰 named 清单、道具组清单），正对原文"细节量不得少于 C 型"的验收口径（12 章 §8.2 双指标）；④名牌件（凸头/拖挂壳）在 T23/T25 内预留额外打磨时间。
- **残余**：曲面形体（帆船壳）最终观感依赖迭代；可用贴图/描边补强轮廓。

### R9｜程序化贴图的文字/手写风格漂移【低】
- **描述**：路牌/警示牌/贴纸文字用系统字体栈 fillText + 逐字符抖动模拟手写（渲染章 §4.2），不同机器字体回退不同（R8 of 13 章）。
- **缓解**：字体栈顺序固定；文案集中 `tex/signageTexts.ts` 常量表便于核对（场景章 J6 内容已拍板）；贴纸主题限定非人物元素（一.6 双层封禁）。
- **残余**：接受字体差异的轻微风格漂移（原文未指定字体）。

## 4. 工作量与优先级取舍

### R10｜内容体量大：4×15+12+13+12 组元素 + 5×16 内饰 + 26 项动效 + 8 公共系统【高】
- **描述**：17 章拆出 48 任务；仅场景元素就 52 组、内饰 named 81 个；单人/小团队推进下 P3+P4 是工作量主体。
- **影响**：工期膨胀；赶工则细节量不达标（三·总则-5 有硬性"不得少于 C 型"比较）。
- **缓解**：①关键路径竖切优先——T18+T23（默认组合）最早合体（M2 里程碑），保证任何时刻都有"能玩的版本"；②部件库复用率最大化（11 章 §1.4 部件表、12 章 §2.7 工厂表，写一次五处引用）；③优先级降序预案（若工期告急按此砍，砍前回写文档并经用户同意）：
  1. 默认组合全保真（海崖/C型/黄昏/晴朗，十一.1）——不可降级；
  2. 时间/天气全维（四/五节是切换玩法核心）——不可降级；
  3. 其余 3 场景 4 车型完整交付——保数量、细节量守底线（16 named/22 行双指标下限），打磨项后置；
  4. P7 打磨项（T41 偶发调参、T42 材质动效）可压缩轮数；
  5. postfx/bloom、可选增强（rim 补丁等）最先关。
- **残余**：降级预案 3–5 档会牺牲观感打磨轮数；需要用户在出现工期信号时拍板，不擅自砍。

### R11｜"注册表可扩展"被验证成本侵蚀【低】
- **描述**：2.5.4/3.6-3 要求"新增不改核心"，T22/T28 用临时测试模块演练验证；若实现中留下隐性反向依赖，演练失败返工面大。
- **缓解**：依赖纪律（content 严禁被 core/render/systems/ui import）从 T01 起作为 review 清单项；演练用 git diff 作证（17 章 T22/T28 验收）；import 检查可用一行 grep 脚本辅助。
- **残余**：无（纪律问题非技术问题）。

## 5. 时间×天气×场景×车型 组合状态一致性（十一.2 L151，400 组合）

### R12｜雾/光照双重叠加与"20 组合合成规则"外的暗角【中】
- **描述**：五-6 只给了一例合成规则（夜间浓雾），其余组合靠公式合成（时间天气章 §3.7）；若场景固有雾（松林 baseFog 0.32）与天气雾分别实现会双重叠加发糊（01 清单存疑 6）。
- **影响**：某些组合脏/糊/过暗，破坏"任意组合均有效"（五-总则 L91）。
- **缓解**：①D6 单通道合成 `fog=(scene.baseFog+time.fogBase)×weather.fogMul` 唯一出口（AtmosphereSystem），场景雾与天气雾是同一个数；②20 组合速查矩阵（时间天气章 §3.7）+ clamp 封顶 + 三原文示例组合专项复核（T34）；③T46 全组合巡游兜底。
- **残余**：个别极端组合（清晨浓雾松林 fog01 封顶）观感需实机标定。

### R13｜句柄泄漏与状态残留（场景/车型切换路径最重）【中】
- **描述**：场景切换要反注册 cloths/lamps/emitters/weatherSurfaces + dispose 动画 + 释放 assets（架构 §5.3）；漏一项则旧场景灯还在闪/布还在飘/计数器虚高；FadeSwap 材质克隆还需把共享 uniform 按引用重挂（UI 章 §11.2-3 风险点，否则克隆件读不到天气参数）。
- **影响**：切换越多越脏，长会话性能劣化、视觉错乱。
- **缓解**：①句柄注册/反注册做成 Director 内成对 API（register 场景时自动记录清单，卸载按清单反向执行）；②T17 验收含"切换 20 轮 DC/内存稳定"泄漏测试；③共享 uniform 以对象引用注入是 ToonMaterialFactory 的强制约定（渲染章 §5.5"按引用注入"），T40 联调专项验证；④极端兜底：FadeSwap 时快照 uniform 值写入克隆件（UI 章 §11.2-3 已声明降级路径，600ms 内天气参数冻结，影响极小）。
- **残余**：无已知无法兜底的路径。

### R14｜过渡中途连点与"离散量"重复切换【低】
- **描述**：快速连点时间档需要 retarget（15 章 §6.5）；离散装饰物（餐具/送货小车/帆船泊位）必须"恰好切换一次"（UI 章 §6.3）。
- **缓解**：retarget 快照机制 + per-transition 布尔；T40/T46 连点专项测试。
- **残余**：无。

### R15｜车型×场景的物理适配冲突【低】
- **描述**：车型章按 `camp.radius ≥ 5.5` 设计，场景章定的半径为 4.0–4.2（场景章 §1.3 表）——两章契约已现冲突（车型章 §11-9 挂起项）；拖挂组合外接半径 5.1、越野帐篷视觉外接 6.6 可能告警。
- **影响**：拖挂/越野在某些场景落位告警或视觉出界。
- **缓解**：①T28 合拢时仲裁：按场景章数值为准（底座 20u 内是 D1 硬约束），回调拖挂组合尺寸或缩小车型（车型章 §11-9 已声明此方向）；②越界只告警不阻断（车型章 §2.1）；③T46 全落位核验兜底。
- **残余**：拖挂组合在服务区大车位（9×5.5）外的场景可能视觉偏大——属可接受的"微缩玩具"夸张。
