## 2. 渲染引擎：Three.js（备选对比）

### 2.1 选择理由

1. **需求几乎逐条踩在 Three.js 的能力面上**：八.2 L121 点名的三渲二实现路径——卡通材质（`MeshToonMaterial` + gradientMap 即渐变色阶 ramp，13 章 §2.2）、反壳描边（一个 ShaderMaterial + 几何克隆即可，13 章 §3.3）、程序化几何（Box/Cylinder/Lathe/Extrude/Tube/InstancedMesh 全部内建）——均不需要任何第三方着色库或插件。
2. **Lathe/Extrude/实例化是原文点名的建模手段**（八.2 L121「基本体、Lathe / Extrude、实例化复用」），Three.js 对这三者是一等公民支持；11 章、12 章全部分章方案（`profileExtrude`、`roundedBox`、`wheel()`、`pleatedBand` 等）都建立在这套 API 上。
3. **onBeforeCompile 注入机制**支撑 13 章 §2.4 的 RGB ramp / 高光带 / rim 三个可选补丁与 WindSystem 布料位移、天气共享 uniform 注入——这是公共系统「写 uniform、不逐顶点」架构（架构 §7-7）的落点。
4. **examples/jsm 随包分发**：13 章用到的 `BufferGeometryUtils.mergeGeometries`（13 章 §6.2 明确「随 three 打包，离线合规」）、可选的 `EffectComposer`/`UnrealBloomPass`（13 章 §7.4 bloom）都来自 three 包内部，**不构成新增依赖**。
5. 生态与文档体量最大，TypeScript 社区类型（`@types/three`）成熟，招错成本低。

### 2.2 备选对比（为何不选）

| 备选 | 结论 | 理由 |
|---|---|---|
| **Babylon.js** | 不选 | 引擎更重（默认携带材质/物理/UI 子系统，安装体积与产物体积都更大）；toon 材质与反壳描边同样要自己搭，相对 three 无收益；`@babylonjs/core` 按需引入可行，但团队三个分章草稿（11/12/13）全部按 three API 编写，换引擎=全部重写 |
| **PlayCanvas（引擎）** | 不选 | 编辑器驱动的云工作流与本项目的「纯本地、零 DCC」约束不合；运行时 SDK 引入成本高于 three，程序化 API 生态更小 |
| **regl / 裸 WebGL2 自研** | 不选 | 阴影、雾、InstancedMesh、纹理管线都要从零造，工作量远超本项目内容开发本身；八.3 的 60fps 目标靠引擎成熟管线兜底更稳 |
| **React Three Fiber / 声明式封装** | 不选 | 引入 React 全家桶（runtime 依赖 ×N），违背「runtime 仅 three」的离线与体积目标；本项目无组件化 UI 需求（UI 是四组分段按钮，D7 已定原生 DOM） |
| **PixiJS（2D）** | 不选 | 项目是三维微缩陈列盒（一.1 L7），维度不符 |

### 2.3 版本策略

- 锁定 **≥0.160 的近期稳定版**（13 章 §2.4 的既定要求），**具体版本号以安装时 `pnpm view three version` 实查为准**，写入 `package.json` 精确版本 + `pnpm-lock.yaml` 提交本地 git，记入 `DEPENDENCIES.md`。
- 原因：13 章 §2.4 的三个 onBeforeCompile 补丁与 three 内部着色器字符串耦合（风险 R1），版本一经锁定不得随手升级；升级 = 重跑 T06 补丁冒烟用例（见 17-任务拆解）+ 回写 DEPENDENCIES.md。
- `@types/three` 与 three 主版本对齐（若安装时 three 包已自带类型声明，则取消该依赖并同步 DEPENDENCIES.md——以实装结果为准）。

## 3. 构建工具：Vite（备选对比）

### 3.1 选择理由

1. **零配置满足全部工程需求**：TS 编译（esbuild 转译 + tsc 类型检查）、dev server（内置浏览器调试走 localhost 回环，符合九.2 L129）、静态产物输出（八.1「纯浏览器运行」）、`import.meta.env.DEV` 区分 dev 计数器与产物（15 章 §1.3、架构 §7-8）。
2. **dev 冷启动与 HMR 快**：本项目源文件数量大（4 场景 + 5 车型 + 10 公共系统 + 部件库/贴图工厂），改一处场景文件要快速回看，这是迭代节奏的保障。
3. **产物形态干净**：`vite build` 产出纯静态 `dist/`（ES module + 静态资源），无运行时框架引导代码，配下面 §6 的离线校验即可交付。
4. 13 章 §4.2 的 SVG data URI 光栅化（异步 Image load）与 Vite 的资源处理无冲突（data URI 不走构建管线）。

### 3.2 备选对比

| 备选 | 结论 | 理由 |
|---|---|---|
| **webpack** | 不选 | 配置量大、dev 冷启动慢；2026 年节点上对纯 TS + three 项目无增益 |
| **esbuild 直接当构建器** | 不选 | 无内置 dev 页面服务与产物清单管理，code splitting/资源指纹要自己拼；省下的配置远小于补的功能 |
| **Rolldown / Rspack** | 不选 | 能力等价但社区类型插件兼容面窄，`vite.config.ts` 生态最稳；若安装时 Vite 默认引擎已切换（Vite 近版方向）则自然受益，无需改变选型 |
| **无构建（原生 ESM + import maps）** | 不选 | three 的 examples/jsm 裸导出依赖路径重写，无构建难以做产物压缩与 tree-shake，体积与加载性能不达标（八.3） |

### 3.3 Vite 配置要点（进 T01 脚手架任务）

- `base: './'`（相对路径，产物可放任意子目录静态服务器下）；
- `build.target: 'es2020'`、`assetsInlineLimit` 默认（本项目几乎无静态资源文件，贴图全程序化）；
- `resolve.alias`：`@core/@systems/@render/@content` 等按 10-架构 §2 目录树配置，配合依赖纪律（content 不得反向 import core）的 code review；
- dev server 仅监听 localhost（九.2：页面只用内置浏览器打开，不需要局域网暴露）。

## 4. 语言：TypeScript strict（备选对比）

### 4.1 选择理由

1. **四套注册表的类型即架构**：架构 §3.2/§3.3 的 `SceneModule` 五部分、`VehicleModule` 四项接口用类型强制（漏实现一个字段编译不过），这是 2.5 L44 / 3.6 L77「新增模块不改核心」的编译期保障；`Registry<T extends RegistryEntry>` 泛型（架构 §3.1）直接落成 TS 代码。
2. **四类句柄（ClothHandle/LampHandle/EmitterSpec/WeatherSurface）是内容层与公共系统的唯一交汇面**（架构 §1 纪律 3）——句柄字段（含 14 章 M1–M4 微调：`windFactor`/`sagAmp`/`pattern`/`snowShell`）由类型定义约束，防止内容模块越过句柄摸系统内部。
3. **400 组合零分支**靠语义通道（`TimePreset.channels` 六通道）与共享 uniform 命名对齐，字符串 key 用 `as const` + 类型收窄，拼错即编译错误。
4. strict + `noUncheckedIndexedAccess` 抓住 `registry.get(id)`、`named['sailboat']` 这类查表访问的空值风险——11 章 §1.5 的具名道具表、12 章的 `VehicleInterior.named` 键表都依赖这个安全性。

### 4.2 备选对比

- **纯 JavaScript**：无接口强制，注册表/句柄约定只能靠 review；原型快但本项目 48 项任务多人线推进，类型是廉价护栏。
- **JSDoc 类型注释**：能力接近但写法冗长，且 `satisfies`/泛型推导/枚举收窄表达受限；与 vite+tsc 工具链无额外成本差。

### 5.1 基线（本机实测，2026-11-08，只读命令）

- `engines` 字段约束 `node >= 20.19`（本机 24.19.0 满足；同时也是 Vite 近版运行的保守下限）。
- 包版本一律精确锁定：`package.json` 写死版本号（`pnpm config set save-exact true` 或安装时 `--save-exact`），加 `pnpm-lock.yaml` 提交本地 git（九.5-b）。

### 5.2 工作流约定

1. **单包项目，不用 workspace**：无 monorepo 需求；`pnpm-workspace.yaml` 不创建。
2. **scripts 约定**（进 T01 脚手架）：
   - `pnpm dev`：vite dev server（内置浏览器打开 localhost，九.2）；
   - `pnpm build`：`tsc --noEmit && vite build`（类型检查前置，类型不过不产包）；
   - `pnpm preview`：本地静态服务预览 dist；
   - `pnpm typecheck`：仅类型检查。
3. **不引入 linter/formatter 依赖**：代码质量靠 `tsc --strict` + 架构依赖纪律 review；理由是「runtime 依赖最少化」目标的延伸，且原文八.1 未要求 lint 工具。
4. **pnpm 构建脚本审批**：pnpm ≥10 默认拦截依赖的 postinstall 脚本；首次安装时 vite 链路的 esbuild 可能需要 `pnpm approve-builds`（或在 `package.json` 预置 `pnpm.onlyBuiltDependencies: ["esbuild"]`）。**该过程与结果必须记入 `DEPENDENCIES.md` 变更日志**。
5. **删除/重装红线**（九.4 L131–135）：node_modules 异常时只允许 `pnpm install --force` 自修复，或整体重命名挪开（`node_modules` → `node_modules_broken`）后全新安装；严禁任何通配符/递归删除命令。
6. **离线能力**：依赖一旦入 store（`E:\_Dev\node\pnpm-store\v11`），后续同版本安装可 `pnpm install --offline`；但**首次安装新依赖版本必然联网**——这是构建期一次性动作，须先过 DEPENDENCIES.md 审批闸门（九.1）。

## 6. 纯浏览器、运行时不联网的保障方式（依赖全部本地化）

八.1 L120 的红线是「**运行时**不依赖网络」；逐层保障如下：

| # | 层面 | 保障手段 | 依据 |
|---|---|---|---|
| 1 | npm 依赖 | runtime dependencies **只有 `three`**，且全部在构建期被打进 `dist/` 产物 bundle；运行时零包管理器解析、零 node_modules 访问 | 八.1、10-架构 §2 末注记 |
| 2 | 网络 import | 代码内禁止任何 `https://` CDN import / import map 远端地址；**构建后用 `grep -rE "https?://" dist/`（排除注释）校验产物无外链** | 八.1 |
| 3 | 字体 | UI 用系统字体栈（`system-ui, -apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei"`，15 章 §4.1），零 web font 零字体文件 | 八.1、15 章 §4.1 |
| 4 | 图标 | `ui/icons.ts` 内联 SVG 程序化生成 20 枚（D7），零图标包、零图片请求 | 八.2、D7 |
| 5 | 贴图 | 全部 Canvas/SVG 程序化生成（八.2）；SVG 光栅化用 data URI → Image，**同文档资源，无网络请求**；`tex/preloadAll()` 在场景装配前 await（13 章 §4.2） | 八.2、13 章 §4.2 |
| 6 | favicon | index.html 内联 SVG data URI（10-架构 §2 目录树注记），零请求 | 八.1 |
| 7 | 运行时 fetch | 架构层面禁止：内容模块接口（SceneModule/VehicleModule）无任何异步加载路径，`SharedAssets` 全同步缓存 | 10-架构 §3.2/§3.3 |
| 8 | 验收 | 交付前做一次**断网运行验证**（关网卡/代理后打开产物，全功能操作一遍）并记入 TASKS.md T47 复盘 | 十一.4 |

> 说明：开发期 `pnpm dev` 的 dev server 是本机回环（localhost），不属于「运行时联网」；vite/HMR 等开发设施只存在于 dev 流程，产物中不存在。

## 7. 构建产物形态与启动方式

### 7.1 产物形态

```
dist/
├── index.html          # 唯一入口（内联 favicon data URI）
├── assets/
│   ├── index-<hash>.js # 全部 TS 源码 + three 打包产物（tree-shaken、minify）
│   └── index-<hash>.css# UI 样式
└── （无图片/字体/模型文件——全部资源运行时程序化生成）
```

- 预计产物体积：JS 主包 gzip 后约 0.4~0.6 MB（three 按 tree-shake 后约占 0.3~0.45 MB gzip + 本项目代码），**此为设计预估值，以 T01 实装后 `vite build` 输出实测并回填 DEPENDENCIES.md**。
- 加载即玩：单 HTML + 双资源，无运行时网络请求（§6 校验）。

### 7.2 启动方式

| 场景 | 命令/方式 | 说明 |
|---|---|---|
| 开发调试 | `pnpm dev` → 内置浏览器打开 dev server 地址 | 九.2：全程仅用内置浏览器，禁 `start`/`open` 与系统浏览器 |
| 构建验证 | `pnpm build` → `pnpm preview` | 产物本机预览，仍走内置浏览器 |
| 最终交付 | `dist/` 目录 → **任意本地静态服务器**（如 `pnpm preview`、`npx serve` 等）打开 | 产物是纯静态文件，宿主只需提供 HTTP 静态服务 |
| 双击直开（可选） | `file://` 直接打开 `dist/index.html` | ES module 在 `file://` 下受浏览器 CORS 限制，默认形态**不支持**；若用户要求「双击即开」，可引入 `vite-plugin-singlefile`（单文件内联构建）——**列为备选依赖，是否引入由用户在审阅时拍板，并先行记入 DEPENDENCIES.md** |
